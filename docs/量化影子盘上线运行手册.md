# 量化影子盘上线运行手册

本功能是只读行情驱动的影子交易系统。它会生成观察状态、买卖信号、模拟成交、持仓
与盈亏，但不会连接券商，也没有真实下单入口。

## 进程与数据链路

生产环境需要持续运行两个现有进程：

```bash
./.local/bin/start_scheduler.sh
uvicorn app.api.app:create_app --factory --host 0.0.0.0 --port 8100
```

Scheduler 已注册以下稳定任务：

| 任务ID | 时间（Asia/Shanghai） | 作用 |
| --- | --- | --- |
| `quant_live_prepare_0920` | 工作日09:20 | 冻结前一交易日状态和观察池 |
| `quant_live_refresh_morning` | 09:30-11:35每分钟20秒 | 补齐三分钟柱并重放 |
| `quant_live_refresh_afternoon` | 13:00-15:10每分钟20秒 | 补齐三分钟柱并在15:05后闭合 |
| `quant_live_startup_resume` | Scheduler 启动时 | 幂等恢复当天任务 |

实际是否为交易日由交易日数据再次确认。服务器内置日历超出覆盖年份时，会回退到
东方财富沪指实际交易日期；盘后本地已有当日日线时优先使用本地事实。不能确认交易日
或缺少上一交易日日线时安全失败，不生成猜测信号。

## 上线前检查

1. `.local/env/.env` 中的 `MONGO_URI` 和 `MONGO_DB_NAME` 指向生产库。
2. Scheduler 日志中存在四个 `quant_live_*` 注册记录，以及两个
   `realtime_minute_*` 交易时段任务。
3. 09:20 后 `quant_daily_results` 存在当天文档，`runtime.data_status` 为
   `waiting_open`。
4. 09:33 后 `runtime.last_complete_bar_at` 开始推进；正常情况下
   `data_status=fresh`。
5. 15:05 后数据完整即进入 `status=closed`；有缺口则重试到15:10再以
   `closed_partial` 硬闭合，并必须排查 `incomplete_codes`。

可用以下请求检查：

```bash
curl -fsS 'http://127.0.0.1:8100/api/v1/health'
curl -fsS 'http://127.0.0.1:8100/api/v1/quant/intraday/latest'
curl -fsS 'http://127.0.0.1:8100/api/v1/quant/signals?action=buy&page=1&page_size=20'
```

## 告警条件

- `runtime.data_status=error`；
- 开盘后超过6分钟仍为 `waiting_open`；
- `evaluated_at` 超过6分钟未推进；
- `incomplete_code_count > 0` 连续两个计算周期；
- 15:10 后状态仍不是 `closed` 或 `closed_partial`；
- 日志出现 `memory safety limit` 或“内存安全上限”。

内存上限触发时不要直接调大常量。先检查行情重复行、观察池异常增长和 MongoDB 查询
计划；服务会保留上一版快照并在下一周期重试，不会写入半成品。

## 前端轮询约定

前端每60秒请求一次
`/api/v1/quant/strategies/{strategy_id}/intraday/latest`。只有
`runtime.version` 变化时，再分页请求该策略的 `/signals`、`/observations` 和
`/holdings`。旧的无策略路径默认指向当前ADX14/E2策略（稳定ID不变、版本2.0.0）。页面必须同时展示数据状态和
最后完整K线时间；
`partial`、`closed_partial`、`error` 不能显示成“今日无信号”。

所有成交价格、费用、持仓和盈亏均为模拟结果。页面应固定显示“影子盘 / 非真实委托”。
观察、信号、成交、持仓和盈亏按 `(strategy_id, trade_date)` 隔离，不能跨策略合并。
策略信号固定三分钟确认；持仓总浮盈、标的当日盈亏和账户当日盈亏按最新完整一分钟
行情刷新。

## 2.0.0迁移与连续记录

正式模型固定为原MACD＋ADX14买入＋E2延期，自2026-08-20空仓起算。
每股初始10万元，期初池由8月19日可知股票冻结；同股现金、持仓、累计盈亏和E2状态跨日连续。
调度器启动会先顺序补齐缺失的已结束交易日，缺少行情或前序账本时报告异常，禁止跳日重置。

迁移先在`quant_daily_results_adx14_v2_stage`生成并校验，可用：

```bash
python -m app.quant.cli.migrate_live_adx14 --end-date 2026-09-04 \
  --output .local/quant/live_adx14_migration_20260906
```

追加`--apply`会先归档旧记录到`quant_daily_results_strategy_archive`及本地gzip备份，再写入正式结果。
迁移资料含逐日新旧快照、代码哈希、账户连续性、因子时点与真实行情覆盖核对。
补录记录的`recording.mode=historical_replay`，真实执行时间在`computed_at`；后续当日运行标记`live`。
旧策略结果和补录不得标为新版当时实时实盘成交。所有交易均为影子模拟。

API的`summary.total_return`分母仅为截至该日曾买入账户的初始本金；已清仓仍计入，从未买入账户不计入公开金额。
首次买入标记`first_buy_at`跨日保存；首次纳入的本金通过`capital_inflow`从当日资产变化中剔除，不能算作盈利。
历史口径转换使用`python -m app.quant.cli.rebase_account_scope --output <目录>`预检，`--apply`备份后原子发布；发布时暂停本项目API和Scheduler，避免旧进程写回旧汇总。
`runtime.data_status=closed_partial`明确表示真实分钟数据仍有缺口，不能显示成完整覆盖。


## 8月20日起点的连续历史补录

执行入口为 `python -m app.quant.cli.extend_live_history`，通过 `--output`、`--run-id` 指定
独立暂存和审计位置，默认只重放和验证；`--apply` 在备份旧集合、重放一致性和账户连续性
校验通过后，原子替换每日结果集合。不能直接修改日期或把新旧起点的结果拼接。

历史采集缺少前收盘参考价时，仅离线补录入口采用经日线涨跌额、比例及原始价格尺度
交叉核验的参考价。实时交易仍要求行情源提供参考价，不使用收盘后数据兜底。
实时采集断点可用本地完整历史分钟聚合日替代，但必须有80个正确时段端点及重叠价格核验；
不插值，不混合半日来源。未通过核验的缺口保持 `closed_partial`。
