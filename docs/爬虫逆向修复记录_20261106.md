本次确认并修复抖音列表和详情持续 HTTP 403 的代码问题，修复微博登录限制分类及探针误报。
调度器和博主内容提取 worker 已重新启动加载新代码，实际采集新增 15 条抖音作品、2 条微博
第一页作品，详情失败 0 条。微博第二页仍需要有效登录会话；用户确认目前没有，保留阻断状态。

## 根因及修复

- 抖音原响应为 HTTP 403、46 字节，包含 `ArgusSecurityPlugin`。现有会话的 `sid_guard`
  本地到期日仍为 12 月 6 日，单凭 403 不能归因于会话到期。
- 当前公开 `runtime_bundler_34.js`（`secsdk-strategy 1.0.42`）通过
  `useWebSecsdkApi('webSignUrl')` 为列表、详情追加 `timestamp` 和
  `x-secsdk-web-signature`。原实现仅有 `a_bogus`，缺少这一层。
- 使用 Camoufox 观察匿名页面请求，并 Hook `CryptoJS.MD5` 验证合成输入，确认新签名为
  `MD5(uifid + '_' + timestamp + '_' + 公开SDK盐 + '_' + 编码查询串)`。
  参数保持原顺序，按 `encodeURIComponent` 规则编码；`a_bogus` 中的 `+ / =` 需要先正确
  URL 编码，防止 `+` 变为空格。新增 `douyin_websign.py` 实现，列表及详情共用签名入口。
  生产继续使用原授权会话中的 UIFID，不使用诊断浏览器的 Cookie，不新增浏览器或 Node 依赖。
- 微博第二页 HTTP 200 内的 `ok=-100` 由 `failed` 改为 `blocked`，明确提示
  `WEIBO_SESSION_COOKIE`。新增 SecretStr 配置，仅发送到微博三个业务 API；默认仍可读取
  公开第一页。访客初始化不能代替登录会话。
- 探针此前在第一页和详情正常、第二页失败时仍返回 `pipeline_ready_ok=true` 且无错误。
  现在保留分页覆盖状态与原因，分页或媒体读取失败时整体就绪标记为 false。
