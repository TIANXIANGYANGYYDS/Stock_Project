# 实时分钟行情补数与恢复

实时快照继续使用腾讯主源与新浪备用源；同花顺网页原生 1 分钟接口用于补偿历史缺口。两者都写入 `stock_realtime_minute_bars`，并通过 `provider`、`source_kind` 和获取时间区分来源。这里补偿的是全部沪深京 A 股，不按情绪题材筛选。

## 历史补数

```bash
/home/txy/miniconda3/envs/MyAgent/bin/python -m app.manually_execute_script.repair_realtime_minutes_ths \
  --start 2026-08-20 --end 2026-09-17 \
  --output .local/market_data_repair_20260919/all_market_universe_v2 --workers 8 --apply
```

不带 `--apply` 时只盘点、下载和验证。相同输出目录可以续跑。完整已完成任务跳过，错误及尚有缺口的任务重试；更换日期或协议必须使用新目录。盘点先查询范围开始前已出现过的全部股票，再逐日纳入新股票及已有分钟股票；不会因前一日没有日线而漏掉连续停牌或停止交易的代码。整日没有观测的股票仍保留在待核范围，因此网格空位不能全部解释为采集故障，也不能自动认定停牌。

同花顺请求参数从当前网页前端脚本解析，运行时不依赖浏览器和手工 Cookie。复用项目已有 `discover_ths_direct_headers`、`discover_ths_market_id` 和 `fetch_ths_direct_bars`，使用 `min_1`、`adjust_type=actual`、指定历史结束时间。HTTP 200 本身不是成功依据，返回窗口还必须通过条数、时间顺序、重复时间和结束时间校验。

同花顺 09:30 集合竞价点单独保留在来源文件中，不映射到连续交易分钟；09:31～11:30、13:01～15:00 的分钟终点减去一分钟，对应本库的分钟起点。OHLC 与成交量、成交额还要通过有限数、非负值及价格范围校验。真实零成交分钟可以保留，不用日线或前值填补空位。

数据库操作只有 `$setOnInsert`，唯一键为 `code + interval + timestamp`。已有实时记录不会被历史下载覆盖。`THS_WEB_ACTUAL_BACKFILL` 表示事后补入的不复权原生分钟；`first_seen_at`、`updated_at` 为实际获取时间，`source_timestamp` 为行情分钟终点。响应内容摘要、修复批次及规则版本附在记录中，原始来源行保存在输出目录的 `responses/`。

补偿先补缺失的 **1 分钟键**，再从完整的分钟网格生成缺失的 5/15/30/60/120 分钟键；不覆盖已有记录。较长周期缺少任何一根组成分钟都不生成。已有分钟的 OHLC、成交量可能仍受快照采样限制，补齐条数并不意味着所有旧记录已经达到交易所逐笔精度。冻结研究输入、角色结果和 HTML 不会随数据库补数自动改写；使用新数据回放时应重新导出到新目录，并记录输入哈希。

## 自动恢复

- 上午任务提前到 09:15，覆盖盘前竞价和上午连续交易；下午仍为 13:00，并保留启动恢复。
- 交易日 09～15 时每 5 分钟运行恢复检查；共用锁防止重复采集，午休及非交易时段直接返回。
- 周一至周五 15:20、17:20、20:20，对最近目标交易日起回看 14 个自然日的分钟缺口执行同花顺补偿。每次重新盘点数据库，纳入迟到的日线及新股名单；补偿后再次盘点真实存储键。同步 HTTP/Mongo 工作放在线程执行，结果位于 `.local/realtime_minute_repair/rolling_YYYY-MM-DD/`。新协议版本需使用新输出目录。
- 主源部分返回时保留已取得的股票；备用源补缺失、非有限数、未来时间及盘中超过 30 秒的陈旧行情。持续不可用的股票至多每 30 秒额外请求一次备用源，避免停牌股不断触发双源请求。原始双方观察均保留，质量不合格的报价不参与分钟聚合。
- 股票名单合并数据库、东方财富和独立新浪分页名单，盘前不按“当日已成交”过滤，盘中后台刷新；名单请求有超时，失败不会无限阻塞采集。
- Mongo 瞬断对同一批绝对值重试，成功前不移除待写分钟，失败时回滚临时聚合，避免丢分钟或重复累加。
- 中断重启先读取对应已持久化聚合桶，已经写出的同一分钟保持不动，从新报价建立累计成交基线；重启时没有观测到的增量不作推算。
- 正常分钟在该股票自身进入下一分钟后才能写出；过时行情不能把累计成交基线回退。午间及收盘的最后一分钟在会话稳定窗口结束时最终写出，避免多次收盘报价反复建立同一分钟。
- 来源时钟校正仅用于会话边界，不再把真实接收时间向行情时间平移。日志包含有效会话报价数、最新源时间、待写分钟和完整周期耗时。

查询 `GET /api/v1/stocks/{code}/intraday?trade_date=YYYY-MM-DD&interval=1m` 可看到补入记录及来源。历史回放可按行情时间使用补数；实盘可知性必须按真实获取时间判断。不能把今天取得的历史数据当作过去实时决策时已经持有的数据。

## 秒级报价与竞价存储（2026-10-07）

2026-10-08 起分为两个独立集合：`stock_realtime_auction_batches` 保存竞价采集批次，`stock_realtime_quote_batches` 保存日内秒级报价及非竞价验证批次。已有 `stock_realtime_minute_bars` 继续保存分钟线及补数。每次轮询一个压缩批次文档，保存当次预期股票名单、两个来源实际收到的报价、原始字段、累计量额、前收盘、开盘价、买卖五档、行情时间、系统接收时间、校验后的接收时间及质量标记。批次和新压缩内容增加 `data_kind=auction|snapshot`。

分表依据校准后的批次采集时间 `observed_at`：09:15（含）～09:30（不含）、14:57（含）～15:00:00 秒进入竞价集合，其余时间进入秒级报价集合。09:25～09:30 的开盘竞价结果也属于竞价数据。每条报价的原始 `phase` 和来源时间保留；迟到或陈旧包不会把整个批次移到另一个采集阶段，空批次同样按采集时间归档供质量审计。

原始记录先写本地 `.local/realtime_quote_spool/` 并 fsync，目标集合确认同一批次 ID 后才移除待写文件；连接中断或确认丢失时保留文件，后续轮询或启动重放。旧 v1 待写文件也从其原始 `observed_at` 推导目标集合，保持原始内容与时间不变。SHA-256 检验压缩内容，重复提交不会生成重复批次。解析不了的响应以缺失数量暴露，不能据此声称完整。此次分表前库里只有一批休市验证记录，没有需要迁移的已入库竞价批次。

上午 09:15～09:30 目标采样间隔为 2 秒，连续交易保持 5 秒；实际周期耗时和观测间隔写入批次，网络及磁盘阻塞会使实际间隔变长。它们是带秒时间戳的公开行情快照，**不是逐秒必达数据，也不是交易所逐笔成交或委托流**。过去没有保存的秒级观察无法从分钟线反推。

竞价分为 `opening_auction_cancelable`（09:15～09:20）、`opening_auction_locked`（09:20～09:25）和 `opening_result`（09:25～09:30），收盘竞价另记 `closing_auction`。盘前竞价保存于独立竞价集合，不混入连续交易分钟网格；09:25 的成交累计值用作开盘后的差分基线。盘前最后成交价可能仍是前收盘，不能把该字段直接当竞价参考价。五档及原始字段保留用于核对，`auction_semantics=raw_book_unverified` 表示公开供应商竞价字段映射尚未经过实际竞价时段验收；尚不据此输出已验证的虚拟匹配量或未匹配量。腾讯档位数量存在以手表示的精度损失，不能视同逐股委托数据。

阶段划分依据交易所规则：[上交所现行交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)。供应商字段含义须另行实测，交易所规则不能代替供应商接口验证。

采集开始时使用腾讯与上交所两处 HTTPS 响应时间交叉校验时钟；两处相差小于 3 秒且偏差不超过 10 分钟才用于行情会话判断。`received_at` 始终保留机器原始时间，校验后的 `observed_at` 单独保存。这是秒级边界保护，不是交易所精密授时。2026-10-07 实测机器快约 290 秒，chrony 未同步且没有可用源；当前运行账号无 sudo 权限，系统授时仍需要管理员修复。

## 查询与完整性

存储编码 `json-gzip-partitioned-v2` 在同一个批次文档内按股票代码后两位分成最多 100 个 gzip 块（`quote_chunks`）。`payload` 保存批次头部，`sha256` 和 `chunk_sha256` 分别校验头部与各块；`compressed_bytes` 为全部压缩块与头部字节数之和。查询单只股票只投影头部及对应块，不再下载和解压全市场报价。原始行序、重复来源、质量标记和全部字段均保留；`decode_batch` 可完整还原，查询兼容旧编码。本地待写文件仍保存完整原始 gzip。

旧批次可在更新查询服务后转换；每批转换前备份原始 gzip，逐字段核对解码内容一致，再按旧摘要原子更新。重复运行跳过已转换文档。备份应保留到验收完成：

```bash
/home/txy/miniconda3/envs/MyAgent/bin/python -m app.manually_execute_script.repack_realtime_snapshots \
  --trade-date 2026-10-08 --output .local/realtime_query_20261008/repack --apply
```

- `GET /api/v1/stocks/002242/auctions?trade_date=2026-10-08`：独立竞价集合，默认 09:15～09:30、最多 1,000 批次；收盘竞价可指定 `start_time=14:57:00&end_time=15:00:01`。
- `GET /api/v1/stocks/002242/snapshots?trade_date=2026-10-08`：独立秒级报价集合，默认 09:30～09:45、最多 200 批次。两个接口均按校准后的接收时间查询，单次最多 15 分钟、1,000 批次，流式解压以限制内存；`collection` 返回查询集合，`possibly_truncated` 提示截断。查询保留原始行情时间，避免把迟到数据当成当时可知。原先通过 `/snapshots` 查询竞价的调用方需改为 `/auctions`。
- `GET /api/v1/market/realtime-quality/2026-09-30`：分别统计两个集合的请求/返回/可用数量及压缩体积，`data_kind`、`collection` 区分来源，另含补数后分钟网格审计。`daily_missing_minutes` 是当日日线名单对应的缺口；历史存在但当日没有日线的股票仍保留在总缺口中待核，不自动判为停牌。分钟键完整不代表 OHLC 精度或秒级全覆盖。
- 原有实时股票接口增加 `quality_issue`、`phase`、`bids`、`asks`，陈旧行情不再只凭 HTTP 200 被当成正常报价。

不设置 TTL、不用前值补出未观测报价。全市场实测 5,571 只、主源全字段压缩约 1.97 MB/批；按计划频率估算约 6.1 GiB/交易日，实际随字段和双源比例变化。低于 10 GiB 可用空间会告警；仍需提前扩容或配置经过校验的长期归档，不能靠 IP 池解决存储容量。当前公共双源直连正常，无需新增付费代理消耗。
