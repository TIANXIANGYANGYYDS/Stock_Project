# 量化任务与龙虎榜补采修复记录

修复日期：2026-10-16。主机仍比校准时间快约 307 秒，不调整系统时钟。

## 故障原因

- 当日量化观察池有 2086 只股票，超过原先写死的 2000 只内存保护上限。开盘准备、盘中刷新及盘后恢复反复失败，查询接口虽然返回 HTTP 200，但业务状态是 `error`，当天没有有效账本。
- 龙虎榜首次执行时，东方财富买方席位报告尚不可用。原任务只在 16:00 执行一轮，轮内三次短暂重试后当天不再自动补采；稍后报告已发布，数据库仍缺当日日档。

## 功能修复

### 量化容量及时间判断

- 有界观察容量从 2000 调整为 6000，支持当前全市场范围和既有持仓、待成交信号；不截断观察池，也不改变选股和交易规则。
- 保留按股票流式读取原始分钟行、单股最多 300 行分钟数据、单股最多 10000 根日线、持仓价格每批 50 只等限制。三分钟柱总量上限随容量调整为 480000，未取消资源保护。
- 自动准备、刷新和启动恢复统一复用现有双来源时间校准。分钟完成数、交易日期和收盘条件使用校准时间；校准失败直接报错，保留已有账本，不按未经验证的主机时间推进计算。Cron 仍由主机调度，实际是否进入业务窗口由校准时间决定。
- 历史补录仍按交易日顺序执行，显式历史重放时间不再额外扣减偏移。

### 龙虎榜持续补采

- 保留稳定任务 ID `stock_billboard_1600`，将调度改为主机时间工作日 16:00–23:45 每 15 分钟触发，继续用交易日历过滤节假日。
- 主机提前触发 16:00 任务时，首轮等待校准后的 16:00。每轮最多尝试三次，失败后由后续轮次继续补采。
- 三份报告分页、日期及席位关联校验全部通过后才保存；同一交易日成功后幂等跳过，不重复抓取或覆盖日档。
- 仍只表示源站当时已披露的观察，不将报告标记为交易所最终完整版本；窗口结束仍失败时保留失败原因。
