# 短线情绪看板接口

**2026-10-22 已重启正式 API 和调度器，并核验大盘 V4.2、题材 V2.4 接口。** 定义与数值规则见[概念定义](短线情绪定义.md)和[判定规则](短线环境判定规则.md)。采集/消费仍以 5 秒为目标周期，环境只在完整的 5 分钟窗口结束后判断。历史已发布的 v1 结果继续保留原版本；新处理的观察使用新规则，不自动重开已定稿日期。

首板为 1 板、中板 2—4 板、高板 5 板及以上；`yesterday_high_board` 已同步为昨日至少 5 板。新增同花顺热度排序、总览题材前五成员、价格/成交额异动事件，以及 `interval=5m` 的环境时间线。

## 给前端的接入速览

交接文件为本文、[OpenAPI 契约](短线情绪OpenAPI.json)和[完整结构示例](短线情绪响应示例.json)。结构示例使用虚构行情，字段契约已与重启后的 `/openapi.json` 核对一致。

沿用现有 API 域名及代理，后端端口为 `8100`；`http://127.0.0.1:8100` 仅用于服务器本机调试。以下前缀均为 **`/api/v1/sentiment`**。全部使用 `GET`，六个 REST 返回 `{meta, data}`，`/stream` 返回 SSE。后端当前未配置 CORS 中间件，浏览器开发环境请通过已有同源代理访问。

| 接口 | 页面用途 | 主要参数 / 数据位置 |
| --- | --- | --- |
| `/dashboard` | 大盘、题材卡片和最近事件 | `scope`；`data.market / boards / themes / recent_events`，题材前五为 `themes[].top_stocks` |
| `/themes/{theme_id}` | 题材详情、前 N 名、完整成员 | `page / page_size / sort`；`data.members.items / emotion / ladder` |
| `/stocks/{code}` | 个股详情 | 六位代码；返回价格、板位、多日多板、热度、历史和事件 |
| `/ladder` | 涨停、炸板、触板梯队 | `theme_id / status / min_streak / board_type / group_by`；`data.groups[].levels[].stocks` |
| `/events` | 行为事件列表、筛选与分页 | `theme_id / code / event_type / after / limit`；`data.items / next_cursor / has_more` |
| `/timeseries` | 大盘/题材环境时间线与统计曲线 | `interval=5m` 看环境，`1m` 看分钟统计，`1d` 看日级事实；可加 `theme_id / start_date / end_date` |
| `/stream` | 页面实时更新 | `scope`；命名事件 `snapshot / resync / update / heartbeat / unavailable` |

默认 `scope=all_a`；主板对照为 `hs_mainboard`。REST 可加 `trade_date` 读取历史。每次先拿总览，再将其 `scope / trade_date / snapshot_id` 传给关联查询。`theme_id` 从总览读取，不使用中文名称或自行拼 ID。

```javascript
const prefix = "/api/v1/sentiment";
const dashboardResponse = await fetch(`${prefix}/dashboard?scope=all_a`);
if (!dashboardResponse.ok) throw new Error(`总览请求失败：${dashboardResponse.status}`);
const dashboard = await dashboardResponse.json();
const theme = dashboard.data.themes.find(item => item.name === "电池");
if (!theme) throw new Error("当前分类没有电池题材");
const query = new URLSearchParams({
  scope: dashboard.meta.scope,
  trade_date: dashboard.meta.trade_date,
  snapshot_id: dashboard.meta.snapshot_id,
  page: "1", page_size: "7", sort: "board_strength"
});
const detailResponse = await fetch(`${prefix}/themes/${theme.theme_id}?${query}`);
if (detailResponse.status === 409) {
  // 当前发布已经更新：重新获取总览、建立新绑定，再请求详情。
} else if (!detailResponse.ok) {
  throw new Error(`题材请求失败：${detailResponse.status}`);
} else {
  const detail = await detailResponse.json();
  // 前七：detail.data.members.items；卡片前五：theme.top_stocks。
}
```

必须同步的展示规则：

1. **分别展示大盘与题材阶段。** 大盘从好到坏为沸点、过热、微热、微冷、过冷、冰点；题材为启动、主升、分歧、高潮、退潮、整理。显示 `emotion.state`，候选 `candidate_state` 只作提示，不替换当前阶段。`support=null` 表示本窗口支持证据未知，可以与已有阶段并存；`state=null` 则展示未初始化及原因。交易所板块和“未分类”返回 `unclassified`。
2. **按后端成员顺序展示。** 默认依次为 `intraday_streak` 降序 → `board_run.limit_up_days` 降序 → `popularity.rank` 升序 → `change_ratio` 降序 → 代码升序。热度不越过板位、多日多板，未上榜/缺失/过期的名次不补零。梯队仍使用自己的分层排序，不从梯队或 SSE 股票子集拼出完整题材排行。
3. **事件显示名称和证据。** 使用 `label / observed_at / source_time / evidence`；按 `event_id` 去重。事件接口升序翻页，总览 `recent_events` 为最近 20 条、按 ID 倒序。新增六类行为及门槛见下文，不以事件推断主力买卖方向。
4. **区分两种更新时间。** 报价/事件目标周期 5 秒，环境判断周期 300 秒。图表的环境阶段取 `interval=5m`；每个点保留自己的版本和质量，`null` 不补零。收盘 `meta.as_of=15:00` 时，环境 `evaluated_at` 仍可为 14:55，因为正式定稿沿用最后真实环境窗口。
5. **保留状态和未知要可见。** `is_final=false` 不称正式收盘；`is_retained=true` 展示真实 `as_of` 和保留原因。`is_stale` 不要求清空历史成员。数值 `null`、条件 `false` 与条件 `null` 分别表示数值未知、条件未通过、条件无法判断。
6. **SSE 用命名监听器。** 对 `snapshot/resync/update` 使用 `addEventListener`，读取 `{meta, data}`；`data.dashboard` 替换总览，股票按 `stocks_upsert/removed_codes/replace_all` 合并。`heartbeat` 只有 `meta`，`unavailable` 只有重试提示。首次连接和重连不包含完整事件历史，需用 `/events` 补齐；跨日或切换范围清空旧游标。浏览器原生 `EventSource` 会在自动重连时发送 `Last-Event-ID`，不要只写 `onmessage`。

错误处理：`404` 为日期/题材/股票不存在；`409` 为绑定版本已更新，重取总览；`422` 为参数或游标错误；`503` 为暂无快照或依赖暂不可用，显示等待并有限重试。请求历史日期时不得将 `404` 展示为零行情。

## 运行入口与数据流

`stock_realtime_quote_batches`、`stock_realtime_auction_batches` → `short_sentiment_live` 调度任务 → 独立看板集合 → REST / SSE。

秒级原始输入自 2026-10-16 起只保留最近 **5 个交易日**，由独立任务自动清理；已经生成的情绪快照、分钟曲线、事件和日级来源继续保留。超出窗口后仍可查询已有情绪结果，但不能依赖已删除的原始批次重建当日秒级路径。规则见[数据库集合清单与清理记录](数据库集合清单与清理记录.md)。

- 调度器每 5 秒运行一次，单次最多消费 12 个批次，按观测时间及批次 ID 排序。采集、消费及上游行情均可能产生延迟；5 秒是目标周期，不是逐笔完整性保证。
- 消费任务为两个行情归档集合创建 `(trade_date, observed_at, _id)` 游标索引，避免每次读取少量批次时排序当天全部压缩行情。
- API 只读已发布快照，不调用全市场采集、不运行情绪计算。同一 API 进程共享最多 1 秒查询缓存；新快照才解压。每个范围、每个交易日的公开快照与内部处理检查点在同一 Mongo 文档原子发布；`short_sentiment_retained` 另外持久保存最后有效的完整观察，重启不依赖进程或浏览器内存。
- 同一范围的单机调度器和手工命令共用文件锁：主板为 `.local/short_sentiment/worker.lock`，全市场为 `.local/short_sentiment/all_a.worker.lock`。两个范围独立更新，一个范围失败不会中断另一个。单机文件锁不支持跨机器写入者；多机部署前需更换互斥方案。
- 先幂等写入事件与时间点，最后原子发布完整日快照；读者按快照中的提交序号查询，失败发布的数据不会提前可见。
- 重启从检查点继续，不把启动时观察到的涨停状态当作全天第一笔。补到游标之前的迟到批次不会自动改写已经发布的路径；修订历史需要单独重建流程。
- 手工回放遇到锁忙会等待重试，不把本次处理零条或不足一批当作回放完成。已开始的盘中处理必须消费完游标后的归档批次，才能进入收盘定稿。
- 题材文件按内容哈希归档到 `.local/short_sentiment/classifications/`；当天重启恢复检查点使用的版本，新的文件版本从下一交易日启用。恢复所需归档缺失或哈希不符时明确报错。
- 主板定稿要求 `market_sentiment_daily` 与对应 `market_sentiment_raw_daily` 同时存在。全 A 股在此基础上读取同次采集的沪深全量原始日线归档，并合并北交所当日收盘报价，保存到独立的 `short_sentiment_daily_sources`。不使用前复权价格判断涨停；日线不会补造封板时间或开板次数。
- 收盘事实以统一的 15:00 时点核算，不受盘后报价时间较晚的盘中乱序校验影响；全市场或任一纳入板块最终统计有效覆盖率不足 98% 时拒绝发布，保留原快照。盘中已观察的触板时间和开板次数继续保留。
- 午休、收盘竞价、收盘待定稿期间，新的观察覆盖率不足 98% 时，整体保留同范围、同交易日、同题材版本的最后有效观察。市场、板块、题材、所有成员及排行使用同一观察，不逐股拼接新旧价格。连续交易期间的异常仍如实发布；没有当天有效观察时明确返回缺失，不借用前一日。
- 采集停止后，任务仍按校准时钟发布时段变化及待定稿原因。状态更新不生成行情分钟点。原始处理检查点继续推进，竞价、失效报价和连续路径间断不会因展示保留而被跳过。
- 每日事实采集现有任务在服务器上海时区的 18:30、20:30、22:30 执行。短线情绪调度每 5 秒触发；校准时间确认的交易活跃时段按此频率消费，午休、闭市和非交易日最多每 60 秒查询一次依赖，有待消费批次时恢复快速处理。依赖齐备、归档消费完成且最终覆盖率达标后自动发布正式定稿。短线任务本身不触发行情补采。服务器时钟偏移可能影响采集任务的实际触发时刻，`as_of` 不因此改写。

注册任务随现有调度器启动，同时维护 `all_a` 与 `hs_mainboard`。手工初始化最近 20 个已有完整依据的交易日：

```bash
/home/txy/miniconda3/envs/MyAgent/bin/python -m app.manually_execute_script.sync_short_sentiment --backfill-days 20
```

处理最近行情，或处理指定日期：

```bash
python -m app.manually_execute_script.sync_short_sentiment
python -m app.manually_execute_script.sync_short_sentiment --trade-date 2026-10-13
```

若需要从已有盘中批次生成某日分钟走势和事件，在该日尚未定稿时先运行 `--trade-date YYYY-MM-DD --replay`；随后不加 `--replay` 执行收盘定稿。已定稿快照不会被这两个命令静默重开。`--backfill-days` 只生成日级观察，不制造过去的分钟路径；全市场缺少某日北交所收盘依据时跳过该日，不用主板日线冒充全市场日线。命令默认 `--scope all_a`，原主板可指定 `--scope hs_mainboard`。

不需要新依赖。部署代码后重启现有 API 和调度器进程。首次暂无快照时，实时入口返回 503，前端展示等待数据；历史日期不存在返回 404。

## 公共契约

REST 响应均为 `{ "meta": {...}, "data": {...} }`。OpenAPI 见 `/openapi.json`，其中有市场、题材、梯队、股票、事件的响应类型。静态摘录见 [短线情绪OpenAPI.json](短线情绪OpenAPI.json)，结构示例见 [短线情绪响应示例.json](短线情绪响应示例.json)。

| 参数 | 说明 |
| --- | --- |
| `trade_date` | 可选 `YYYY-MM-DD`，省略读取最新已发布交易日；不会把上个交易日伪装成今天 |
| `scope` | 默认 `all_a`，覆盖五个板块；`hs_mainboard` 仅沪深主板；其他范围返回 422 |
| `snapshot_id` | 可选，从总览取得后传给后续查询；与服务当前可读快照不同返回 409，需要刷新总览 |

以上公共参数适用于六个 REST 接口。SSE 支持同样的 `scope` 参数，始终跟随该范围的最新交易日。两个范围的快照、事件、走势和查询缓存独立。

全市场快照编号示例：`all_a:2026-10-14:00003408`；原主板保持 `2026-10-14:00003409` 的格式。编号应当作为不透明字符串原样传递。切换范围时重新获取总览，清空旧事件游标；快照编号不匹配返回 409，跨范围事件游标返回 422。

| `meta` 字段 | 说明 |
| --- | --- |
| `trade_date / scope / snapshot_id` | 日期、范围、该日提交序号标识 |
| `as_of / generated_at` | 展示数据的实际观测截止时间、此次发布生成时间；保留观察不改写 `as_of`，逐股来源时间另见 `source_time` |
| `session` | `opening_auction / continuous / lunch / closing_auction / closed_pending_final / closed` |
| `is_final` | 是否已按每日事实定稿；盘后也可能仍为 false |
| `is_retained` | 是否展示同日最后有效的完整观察；true 不代表正式收盘结果 |
| `retention_reason` | `nontrading_invalid_observation` 非连续交易期间新观察无效；`session_ended_without_new_observation` 时段结束且没有新观察；`no_same_day_usable_observation` 没有可保留的同日观察（此时 is_retained=false）；其他情况为 null |
| `retained_from_snapshot_id` | 保留数据来源的观察编号，仅用于溯源，不是可查询的历史版本句柄；接口绑定应使用当前 `snapshot_id` |
| `processed_as_of` | 内部已处理的最后原始观察时间，保留时可以晚于 `as_of`；不是报价截止时间或收盘价确认时间 |
| `finalization` | `{status, pending_reasons}`；status 为 `not_due / pending / finalized`，待定稿时返回明确依赖/质量原因，正式定稿后原因清空 |
| `age_seconds / is_stale` | 快照年龄与过期标志；正常午休不按持续交易计算延迟，缺少上午收尾仍提示过期 |
| `clock_offset_seconds / clock_basis` | 沿用采集时钟校准；校准后的当前时间 = 服务器时间 + 偏移秒数。`calibrated_capture` 表示采用采集校准，`system` 表示系统时钟。年龄及交易时段判断使用同一时钟，停止采集后年龄仍持续增长 |
| `coverage` | 有效统计家数 / 应统计家数，空分母为 null |
| `classification_version / rule_version` | 题材文件 SHA-256、观察规则版本 |
| `universe_basis` | 名单依据：当日每日名单、昨日名单加新有效观测，或缺少昨日依据时的采集请求名单 |
| `included_boards` | 当前范围包含的板块 ID |
| `history_available_sessions` | 当前快照之前、近 20 个交易日中有同范围日级依据的日期；缺失历史不拼接连板，已有主板原始历史仍用于主板个股的多日多板结构 |
| `classification_basis` | `fixed_catalog`，历史题材统计属于固定题材池回看 |
| `price_basis / sample_interval_seconds` | `raw` 不复权价格、目标采集周期 5 秒 |
| `data_mode` | `observed_snapshots / retained_observation / daily_final` |

金额人民币元，数量为股，价格为元；个股 `change_ratio`、覆盖率及 `values` 的比例字段使用小数，`0.1 = 10%`。环境 `facts.B / U / D3 / D5 / Q10` 等占比使用 0—100，`M / A30 / V30` 等使用标准化 r10 口径，不能再次套用百分比转换。时间为含时区的 ISO 8601，可能使用 `+08:00` 或 `+00:00`，前端统一按 `Asia/Shanghai` 显示；不要对来源时间再次手工减去约五分钟偏移。未知使用 `null` 与 `missing_reasons`，空样本比例不补 0。

保留观察的 `coverage`、逐股 `valid / eligible / is_stale / missing_reasons` 均描述 `as_of` 时的真实质量；原本缺失、异常、ST、停牌或无限价股票仍保持原有标记。`meta.age_seconds / meta.is_stale` 则描述该观察相对查询时刻的年龄，不能因顶层过期标志而清空仍可回看的成员。展示应同时说明“截至实际时间、收盘待定稿、保留观察”，不能称为 15:00 收盘数据。

`finalization.pending_reasons` 当前包括 `daily_summary_missing`（每日事实汇总缺失）、`daily_raw_missing`（每日原始事实缺失）、`daily_archive_missing`（全量日线归档缺失）、`bse_close_archive_missing`（北交所收盘归档缺失）、`daily_source_invalid`（归档校验失败）、`archive_backlog`（盘中归档未消费完）、`final_coverage_below_threshold`（最终市场覆盖不足）、`final_board_coverage_below_threshold`（最终某板块覆盖不足）、`replay_in_progress`（明确以回放模式处理）。前端应容忍后续新增原因代码并保留原文。

公开 `snapshot_id` 表示一次完整发布；进入保留状态、待定稿原因变化、正式定稿均可能产生新编号。服务仅提供每个范围、每个交易日最新发布版本，旧编号仍返回 409。收到 409 后重取总览及关联数据，不反复重试旧编号。

## 2026-10-15 保留机制的前端适配

页面布局由前端自行决定；API 前缀、鉴权和代理配置不变。数据接入需要同步以下行为：

1. 先获取 `/dashboard?scope=all_a`，使用返回的 `trade_date / snapshot_id` 请求成员与走势。切换范围后重新获取总览，不解析快照编号。
2. 题材前七请求 `/themes/{theme_id}?scope=all_a&trade_date=YYYY-MM-DD&snapshot_id=...&page=1&page_size=7&sort=board_strength`。后端默认已改为该排序；只需要涨幅排序时显式传 `sort=change_ratio`。完整成员包含未触板及被排除成员，后者应保留排除标记，不能当作有效统计样本。
3. `is_retained=true` 时可展示成员和统计，并注明真实 `as_of`、待定稿、保留原因及数据质量。顶层 `is_stale=true` 表示观察已较旧，不应据此清空成员；`is_final=false` 时不能称为正式收盘。保留来源编号仅供溯源，查询继续绑定当前发布编号。
4. 全天曲线直接请求 `/timeseries?interval=1m`；题材曲线再加 `theme_id`。按每个点自己的数值与质量绘制，null 断开，不用最后有效值补线，也不因当前快照过期而丢掉全天有效点。正式收盘点从 `interval=1d` 获取。
5. SSE 首次、重连、更新均提供同一持久发布的元数据。SSE 总览含题材 `top_stocks` 前五；完整成员分页仍通过 REST 获取，收到新编号或正式定稿状态后重新请求成员与走势；409 时重取总览后重试。浏览器刷新、首次访问无需本地历史缓存即可读取保留观察。

## 接口

### GET /dashboard

返回 `market`、`boards[]`、`themes[]`、最近 20 条 `recent_events`、观测股票去重数 `unique_stock_count`。

`boards[]` 按沪市主板、深市主板、创业板、科创板、北交所排列，各项含 `board_type / name / member_count` 及相同的统计、反馈和情绪字段。`market` 按全范围股票代码去重计算，题材成员可以横跨多个板块。

扩围前保存的 `hs_mainboard` 历史快照没有分板块明细，查询时 `boards` 返回空数组；其原有市场和题材统计继续可用。

每个市场/板块/题材统计包含 `values`、`feedback`、`emotion`、`missing_reasons`；市场和题材另含 `recent_activity`。题材额外包含稳定 `theme_id`、名称、原始成员数 `member_count`、当前范围成员数 `scope_member_count`；总览中的每个题材另带 `top_stocks`，按默认成员排序返回前 5 只及完整个股字段。更多成员使用题材详情分页。

题材默认按当前涨停数量降序、涨停占比降序、题材 ID 排序。该排序不是主线确认或资金流入判断。

### GET /ladder

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `theme_id` | 无 | 从总览获得的题材 ID；未分类为 `unclassified` |
| `status` | `limit_up` | `limit_up` 当前涨停价、`opened` 触板后当前打开、`touched` 当日已触板 |
| `min_streak` | 无 | 1～100；打开列表按冲击目标高度筛选 |
| `board_type` | 无 | `sh_mainboard / sz_mainboard / chinext / star / bse` |
| `group_by` | `theme` | `theme / market` |

返回 `groups[] -> levels[] -> stocks[]`。每层含 `height`、`count`、`height_basis`。高度未知为 null，排列在已知高度之后；同高度按首次观察到触板的时间及代码排序。

`unique_count` 是股票去重数；`membership_count` 是分组展示次数，一股多题材时后者可能更大。市场汇总禁止直接对题材计数求和。

### GET /themes/{theme_id}

返回题材统计、`ladder`、分页 `members`。`page` 默认 1，`page_size` 默认 50，最大 200。`sort=board_strength` 为新默认值：依次按 `intraday_streak` 降序、`board_run.limit_up_days` 降序、`popularity.rank` 升序、`change_ratio` 降序，最后按代码升序稳定排序。每个字段的 null 排在该字段有效值之后，不补零，也不用 `target_streak` 替代。`sort=change_ratio` 可继续使用仅按涨幅降序的兼容排序。

`members` 含 `items / total / page / page_size / sort / sort_fields`。成员包含未触板股票，也保留被排除/缺行情成员的状态，不能将后者当作有效统计样本。前七直接请求 `page=1&page_size=7&sort=board_strength`；与同一快照完整成员列表的前七一致。不要从只含触板股的梯队或 SSE 股票子集生成完整成员排行。

同花顺热度来自现有 `stock_ths_hot_rank_snapshots`，使用**同交易日、`observed_at <= meta.as_of` 的最近一份榜单**，并随行情快照冻结。采集已校准的时间直接比较，不再重复加减服务器约五分钟时差。最久接受 900 秒；超过后标记 `stale`，不参与排序。午休长时间没有新榜单也可能过期，恢复后等待下一次实际采集。

`popularity` 字段：

| 字段 | 说明 |
| --- | --- |
| `provider` | 固定 `ths` |
| `rank / heat / rank_change` | 同花顺名次、热度原值、来源的名次变化；以 `rank` 升序排序 |
| `status` | `ranked` 已上榜；`not_ranked` 当前前 100 未上榜；`missing` 没有当时可用榜单；`stale` 榜单已过期 |
| `snapshot_id / observed_at / age_seconds` | 热度来源编号、采集时间、相对行情观察的年龄 |
| `max_age_seconds` | 900 |

未上榜、缺失和过期均返回 `rank=null, heat=null`，不补为零。`meta.popularity` 提供整份榜单状态。热度字段同时进入题材成员、总览 `top_stocks`、个股、梯队和 SSE 的股票对象；旧快照没有冻结的热度时明确缺失，不拿今天榜单填历史。

### GET /stocks/{code}

六位股票代码。返回个股事实、近 20 个交易日 `board_history`、所属题材名称、该股事件分页首批 `events`。更多事件通过 `/events?code=...&after=...` 获取。

| 个股字段 | 口径 |
| --- | --- |
| `price / change_ratio / open_change_ratio` | 当前价格、相对可比昨收的涨幅、开盘涨幅 |
| `amount_yuan / turnover_ratio / drawdown_from_high_ratio` | 当日累计成交额、换手率、相对当日已知最高价回撤 |
| `limit_up_price / limit_down_price / limit_rule` | 当日限价和来源；不按近似涨幅识别涨停 |
| `is_limit_up / is_limit_down` | 当前价格是否等于当日限价，未知为 null |
| `limit_status` | `sealed / at_limit / opened / not_touched / unknown` |
| `is_sealed` | 盘口可核验且买一位于涨停价、有买量、卖盘为空时为 true；盘口缺失为 null |
| `seal_amount_yuan / seal_volume_shares` | 当前已观察封单；没有有效盘口为 null，不等于成交保证 |
| `touched_up` | 快照曾观察到涨停价，或供应商当日最高价确认触板 |
| `first_touch_at / first_seal_at` | 首次观察到触板/盘口封板的来源时间，不能冒充交易所首次发生时间 |
| `last_open_at / last_reseal_at` | 连续有效观测确认的最近离开/回到涨停价时间 |
| `observed_open_count` | 实际观察到的离开涨停价次数；0 次观察不表示市场全天没有开板 |
| `confirmed_streak_before_today` | 前一交易日收盘确认的连续板高度 |
| `intraday_streak` | 观察时已实现的连续板高度；打开时为 0，未知为 null；只有正式定稿后为最终高度，收盘待定稿仍为暂定值 |
| `target_streak` | 昨日高度 + 1，即当天冲击目标，不随开板丢失 |
| `board_run` | 多日多板结构，见下文 |
| `theme_ids / attributed_theme_id` | 多题材关联；当前没有自动上涨归因，后者保持 null |
| `eligible / excluded_reason / valid` | 是否参与当前统计、排除原因、行情是否有效 |
| `source_time / received_at / provider` | 行情来源时点、系统接收时点、来源 |
| `timing_basis / path_complete` | 当前为快照观测，`path_complete=false`，不声称逐笔完整 |

多日多板 v1：最多回看 20 个市场交易日，向前连接中间最多相隔一个非涨停日的板；两个连续非涨停日或未知日停止连接，段首段尾都是涨停日。返回 `window_days`、`limit_up_days`、`label`、`is_final`、`rule`。例如尾部连续 3 板且阶段有 11 天 8 板时，连板梯队属于 3 板。未知日之前不拼接；这是已知窗口标签，不是完整行情阶段身份。

### GET /events

`after` 为上一页 `next_cursor`；`limit` 默认 100，最大 200。可按 `theme_id`、`code`、`event_type` 过滤。返回 `items / next_cursor / has_more`，按事件 ID 升序。

保留事件类型 `first_touch / first_seal / open / reseal / limit_down / emotion_changed`；新增如下行为，`event_type` 可直接过滤：

| 类型 | 展示名称 | v1 触发条件 |
| --- | --- | --- |
| `rapid_rise` | 暴力拉升 | 最近 180 秒价格涨幅 ≥3% |
| `rapid_fall` | 急速下跌 | 最近 180 秒价格跌幅 ≤−3% |
| `quick_rebound` | 快速反弹 | 最近 300 秒窗口先出现 ≥1% 下跌，随后从该窗口低点反弹 ≥2% |
| `high_dive` | 高台跳水 | 最近 300 秒窗口先出现 ≥1% 上涨，随后从该窗口高点回撤 ≥2% |
| `volume_surge` | 放量异动 | 最近约 60 秒成交额按实际采样秒数归一到每分钟，≥此前约 240 秒每分钟均额的 3 倍，且该段实际成交额 ≥1,000 万元；基准必须为正 |
| `open_limit_down` | 打开跌停板 | 同一连续路径中，从跌停价变为高于跌停价 |

数值是本项目初版阈值，价格比例使用真实未复权价格变化，**不是 r10**。事件类别参考[同花顺短线精灵](https://www.10jqka.com.cn/ad_mar/help/dxjl3.html)与[东方财富行情异动](https://quote.eastmoney.com/changes/)；[东方财富快速反弹示例](https://finance.eastmoney.com/a/202607133803448988.html)披露了五分钟上涨超过 2% 的案例。这些资料用于选择可展示的行为，不代表复刻供应商私有算法。

新增事件带 `label`、`rule_version=price-behavior-v1`、`evidence`（实际幅度/价格/成交额及门槛）和 `cooldown_seconds=300`。阈值从未满足变为满足时触发；同股同类型 300 秒内不重复。不同类型可能同时触发。观察历史随检查点持久化；超过 15 秒断流、换源、午休、跨日均重建窗口；重复或倒序来源时间不推进检测，累计成交额回退后重建成交额窗口。窗口锚点只取目标时间之前最近的样本，允许最多 15 秒采样误差；日线定稿不补造此类事件。无逐笔方向依据时不生成“大笔买入/主力买入”。

记录 `event_id`、`snapshot_id`、股票/题材、来源时间、观测时间和 `timing_basis`。相邻来源时间必须前进且间隔不超过 15 秒，才能生成开板/回封；重复、乱序、缺口、竞价数据不补造这些事件。

主板游标格式为 `YYYY-MM-DD:八位提交序号:五位事件序号`，全市场格式增加 `all_a:` 前缀；跨范围、跨日期或非法游标返回 422，游标晚于当前快照返回 409。事件基于稳定 ID 幂等保存，客户端按 `event_id` 去重。

### GET /timeseries

`interval=1m|5m|1d`，默认 `1m`；`start_date / end_date` 默认快照日期；可传 `theme_id`。1m 查询跨度最多 7 个自然日，5m 最多 186 个自然日，日级最多 366 个自然日，结束日期不能晚于本次快照日期。

返回 `items[]`：时间点、实际 `as_of`、快照编号、版本、市场或题材统计。分钟点使用该分钟首次提交的观测，不是分钟收盘，不插值、不跨缺口连线；日级点仅来自收盘定稿。某天没有消费过盘中快照时，不会凭日线生成分钟曲线。

保留期间仍返回当天全部已提交的真实分钟记录，包括 `as_of` 之后、`processed_as_of` 以内的无效观察及其 null；不把保留价格复制为横线，不因为最新分钟无效而删除之前的有效走势。曲线逐点读取 `items[].market` 或 `items[].theme` 的质量和缺失情况，不能用顶层 `meta.is_stale` 将全天曲线整体置空。时间点自己的快照编号表示归档来源，不是历史完整成员快照的查询入口。

`interval=5m` 返回本轮接入后实际处理的完整窗口，包含各自的环境、条件与证据；与分钟行情点独立保存。缺失数据窗口如实返回质量信息，不能用最终收盘倒填。旧日期没有新规则的五分钟记录时返回空列表，不从旧 v1 每分钟结果伪造。

收盘定稿更新总览、题材、梯队、个股和 `interval=1d`，不会把最终日线事实回填到 `interval=1m`。因此，日级收盘覆盖完整时，尾盘分钟点仍可能因集合竞价或当时行情不齐而保留 `null`；查询当日最终结果应使用 `meta.is_final=true` 的快照或日级点。

### GET /stream

SSE，`scope` 默认 `all_a`，目标每 5 秒检查新快照，支持 `Last-Event-ID`。消息 `id` 为快照编号。

- 首次连接发送 `snapshot`：完整总览、当前触板/跌停观察股票、`replace_all=true`。
- 重连 ID 无法匹配当前快照时发送 `resync`：重新替换全部状态。需要补齐完整事件历史时使用 `/events` 游标接口。
- `update` 包含 `dashboard`、`stocks_upsert`、`removed_codes`、`replace_all=false` 以及事件分页 `events`。即使股票当前价格恢复原状，中间的开板、回封仍会通过事件查询补入。
- `stocks_upsert` 包括已触板且打开的股票，前端根据 `is_limit_up` 判断是否保留在“当前涨停”列表。移出整个观测集合时按 `removed_codes` 删除。股票以代码去重，再按 `theme_ids` 展示。
- 保留及正式定稿使用与 REST 相同的持久发布和 `meta`。首次连接、重连和更新后，题材完整成员/前七需按消息中的 `scope / trade_date / snapshot_id` 请求 `/themes/{theme_id}`；即使 `stocks_upsert` 为空，编号或定稿状态变化也应重新拉取当前题材和走势。未触板股票不会因此丢失。
- 保留期间市场、题材、股票统计截至 `as_of`；事件分页与分钟归档遵循当前发布的提交序号，可以包含 `processed_as_of` 以内的真实处理记录。保留机制不补造封板事件。
- 无新快照发送 `heartbeat`，其中的最新 `meta.is_stale` 用于提示采集停止。跨交易日发送 `snapshot` 并清空旧状态。
- 事件单次最多 200 条，积压在后续消息继续补齐。客户端按稳定 `event_id` 去重。
- 代理需关闭流式缓冲，响应已设置 `X-Accel-Buffering: no`、`Cache-Control: no-cache`。

## 指标与情绪规则

`values` 包含：应观测/有效/缺失/排除数量、覆盖率、涨跌停数量、涨停占比、触板与未封住数量、当前未封住比例、曾观察开板比例、涨跌平数量、上涨占比、涨幅中位数、成交额、涨跌超 5% 数量、回撤至少 8% 数量、最高连续板、各级梯队、一进二和二进三比例。

- 当前未封住比例 = 已触板但当前不在涨停价的家数 / 已触板家数。
- `seal_rate` = 当前处于涨停价的家数 / 已触板家数。这是价格状态统计，不要求每只股票都有盘口封单。
- `ever_open_ratio` = 曾观察到离开涨停价的家数 / 曾以快照观察到涨停价的家数；仅有日线最高价触板记录的股票不进入该分母。
- 覆盖率不足 98% 时，汇总市场指标返回 null，并保留质量计数和原因；不把缺行情当作股价下跌。个股列表仍可展示有效观测，但不能伪称完整市场统计。
- 五分钟大盘环境按全市场 98% 门槛检查，不因单个板块低覆盖整体失效；方向、题材以及收盘定稿继续执行各自质量检查。`emotion.data_quality` 中的 `policy` 为 `market_coverage_with_local_diagnostics_v1`，`minimum_coverage` 为 0.98，`window_minimum_coverage` 为五分钟最低市场覆盖，`board_minimum_coverage` 为各板块最低覆盖，`incomplete_directions` 列出质量不完整的方向。旧版本结果可能没有此字段。
- 昨日反馈固定使用上一交易日的成员；包括昨涨停、昨首板、昨连板、昨 5 板及以上、昨炸板五个群体。返回样本数、观测数、开盘/当前涨幅中位数、红盘数、跌超 5% 数量、跌停数和当前涨停比例。停牌或缺行情导致当前群体不完整时比例/中位数为 null；今日变 ST 不自动从昨日样本删除。
- `recent_activity` 是最近 300 秒观察到的全部个股事件分类计数，包含新增的拉升、下跌、反弹、跳水、放量和打开跌停。

环境综合版本为 `short-sentiment-market-v4.2-theme-v2.4`。每个 `emotion.rule_version` 保留对应纯规则的精确版本标识，`validated_for_trading=false`。大盘好坏顺序为沸点、过热、微热、微冷、过冷、冰点；题材使用启动、主升、分歧、高潮、退潮、整理。交易板块 `boards[]` 继续返回事实统计，其 `emotion.status=unclassified`，不把交易所板块当作题材套用阶段；未分类股票集合也不强行判题材情绪。

| `emotion` 字段 | 含义 |
| --- | --- |
| `state / state_since / previous_state` | 已确认阶段、起点、上一个阶段 |
| `candidate_state / candidates` | 尚在累计确认的目标、已累计窗口及要求；候选不等于已切换 |
| `status` | 已有确认阶段为 `confirmed`；无可恢复阶段且尚未完成初始化时为 `insufficient_data`；不适用为 `unclassified` |
| `support / support_status` | 当前保持证据成立 / 不成立 / 无法计算，及具体解释；`confirmed` 不代表当前支持一定成立 |
| `entry / hold` | 各进入、保持条件的三态结果：true / false / null |
| `facts / evidence / counter_evidence` | 本窗口数值、进入条件、未成立或未知的保持条件 |
| `evaluated_at / evaluation_interval_seconds` | 最后完整窗口判断时间，周期 300 秒；报价可能已更新但阶段没有再次判断 |
| `last_supported_at / support_unknown_reasons` | 最后获得支持的时间、当前缺少哪些支持证据 |
| `structure` | 大盘主线方向的候选、持续窗口、已确认方向及支持事实；不等于个股龙头 |
| `cycle_id / startup_cohort / high_cohort / exit_evidence` | 题材周期、固定跟踪组及持续失效退出证据 |

运行时将每个分钟边界之前实际收到、来源时间距离边界不超过 30 秒的有效报价用于该分钟观察，任何边界之后的价格都不回填上一分钟。每天只在 09:35—11:30、13:05—14:55 的五分钟边界计算，累计确认、跨午休/跨日保持、退出等条件直接调用已确认状态机；滚动指标保留同一半日的最近 36 分钟输入。状态、候选计数、价格基准和固定组在检查点中恢复。缺少分钟、滚动预热和固定风险组缺价均保留真实未知；已有已确认阶段继续沿用，不能把未知强行解释为退潮。

第一次从旧 v1 检查点升级时，旧标签不能映射成六阶段，需由新观察重新完成窗口初始化。已定稿旧日期及其历史曲线保持原版本，当前任务不自动重算历史；若仅有日线归档而没有新规则的盘中窗口，有可恢复阶段则沿用并标记当日支持未知，否则保持未初始化。收盘定稿保留最后真实窗口，标记 `is_carried_to_close=true`，不使用日线制造 15:00 阶段变化。新增接口字段不构成自动交易策略；个股龙头、角色、卡位和资金方向仍没有被自动推断。

## 当前数据边界

- 支持沪市主板、深市主板、创业板（包括 `302` 段）、科创板和北交所。当前北交所使用 `920` 新代码；不会把新三板或旧代码别名一并计入。ST、可识别退市整理、已知停牌和无限价证券排除。实时停牌状态缺乏独立来源时保留为缺行情，不根据零成交擅自认定停牌。
- 实时优先使用供应商逐股限价，不能统一按涨幅 10% 判断。创业板/科创板每日归档使用不复权可比昨收、20% 常规规则及上市前五个交易日排除；北交所收盘使用当日供应商实际限价，上市首日不计入涨跌停统计。特殊状态不能核验时保留缺失。
- 腾讯归档字段 47/48 提供当日涨跌停价，38 为换手率百分数，33/34 为最高/最低价。值必须通过价格有效性检查；其他来源没有这些字段时保持未知。实时证券状态以行情名称及供应商限价为观测依据；每日定稿中沪深状态以每日原始状态为准，北交所使用供应商名称及收盘报价证据。北交所分母保留采集请求名单内的缺行情股票，可能包含尚未有有效交易的代码，缺失不当作下跌或非涨停。
- 北交所部分盘中归档存在供应商报价时间回退、旧报价及备用来源缺少限价的情况。这些报价仍按 `out_of_order / stale_source_time / unknown_price_limits` 标记缺失；全市场覆盖不足 98% 时整体情绪也可能为数据不足。收盘依据覆盖完整不代表盘中每个采样点完整。
- 集合竞价和非交易价格不作为连续交易路径判定；收盘竞价期间优先展示最后有效观察，没有同日有效观察时才显示数据不足。尚未对竞价未匹配量做推断。
- 当前实时有效阶段只接受 `continuous` 和 `session_close`；14:57 后的 `closing_auction`、15:00 后的 `outside_session` 报价不计入有效统计。供应商报价时间不同步时，15:00 的首批分钟观测也可能不齐，不能将其视为最终收盘结果。
- 午休无效报价不会覆盖最后有效的完整展示观察；原始分钟记录仍如实保留覆盖率为 0、统计为 null 的点。没有当天可保留观察时，`session=lunch` 和 `is_stale=false` 不等于行情完整，不能把 null 展示成零涨停。
- 当前题材库没有可靠的历史生效日期，历史题材走势明确为固定池回看；成员关联不等于本次上涨原因。每个范围在当日首次生成快照时冻结分类版本，盘中修改文件不会改变该日已有归属；重启继续使用归档版本。
- 不提供不可核验的逐笔封板时间、完整开板次数、排队成交、主力净流入。没有盘口的收盘记录封单为 null。
- 放量异动只比较同日连续路径内的成交额增量，不计算盘中累计成交额/昨日全天成交额比值，也不把它解释成主动买入资金。
