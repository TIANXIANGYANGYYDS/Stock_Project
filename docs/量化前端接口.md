# 量化策略前端接口 v1.2（已交易账户口径）

只对真实策略名称及含名称的存储标识做匿名处理；账户结果、参数、指标、判断依据、确认进度、
执行尝试及运行数据均可展示。字段采用显式类型，不直接暴露恢复快照的冗余结构。策略使用公开编号 `strategy_1`、展示名“策略1”；
将来有其他公开策略时，从目录读取名称，不在前端推断编号的含义。当前目录只有策略1。
各策略、各股票账户独立核算。服务端只返回明确列出的字段，完整类型见 `/openapi.json`，也可下载[独立 OpenAPI 文件](量化前端OpenAPI.json)。

## 页面与接口

推荐页面包含资产总览、收益曲线、逐股账户、观察列表、信号列表、成交明细、当前持仓、当日平仓；
参数、候选和退出判断可放在详情抽屉或独立页签中，数据完整提供，页面按需展开。
所有接口为只读 GET，不提供下单操作。策略级路径的前缀是：

```text
/api/v1/quant/strategies/{strategy_id}
```

| 路径 | 用途 | 可选参数 |
| --- | --- | --- |
| `/api/v1/quant/strategies` | 公开策略目录 | 无 |
| `前缀/overview` | 资产、收益、当日成交与数据状态 | `trade_date` |
| `前缀/performance` | 按日期升序的资产、收益曲线 | `start_date`、`end_date`、分页 |
| `前缀/observations` | 观察列表 | `trade_date`、`action`、`state`、`state_detail`、`code`、`snapshot_id`、分页 |
| `前缀/signals` | 买卖信号 | `trade_date`、`action`、`status`、`status_detail`、`code`、`snapshot_id`、分页 |
| `前缀/executions` | 已成交模拟买卖，支持跨日分页 | `trade_date`或`start_date`＋`end_date`、`code`、`action`、`snapshot_id`、`history_version`、分页 |
| `前缀/holdings` | 所选日期的持仓及估值 | `trade_date`、`code`、`snapshot_id`、分页 |
| `前缀/closed-trades` | 所选日期平仓及已实现盈亏 | `trade_date`、`code`、`snapshot_id`、分页 |
| `前缀/accounts` | 曾买入的逐股独立账户，包含已清仓账户 | `trade_date`、`code`、`has_position`、`snapshot_id`、分页 |
| `前缀/preselections` | 买入预选及原因、参考价格 | `trade_date`、`code`、`status`、`snapshot_id`、分页 |
| `前缀/sell-candidates` | 卖出候选及原因、参考价格 | `trade_date`、`code`、`snapshot_id`、分页 |
| `前缀/exit-decisions` | 持有、延期、退出判断记录 | `trade_date`、`code`、`action`、`snapshot_id`、分页 |
| `前缀/daily-results/latest` | 最新完整公开业务快照 | 无 |
| `前缀/daily-results/{trade_date}` | 一次获取指定日期各模块 | 无 |
| `前缀/intraday/latest` | 最新总览，兼容已有入口 | 无 |

除目录外，去掉 `/strategies/{strategy_id}` 的短路径也可用，默认读取策略1；短路径可以传
`strategy_id=strategy_1`。前端推荐始终使用策略级路径。未登记编号返回404。

`trade_date`、`start_date`、`end_date` 均为 `YYYY-MM-DD`。省略 `trade_date` 返回最新已有
盘中快照，不承诺就是今天；页面必须显示响应的实际日期。详情找不到指定日期返回404。
`performance` 只返回真实已有记录，无记录时为空列表，不填充周末、缺失日，不外推收益。

## 共用字段与分页

单份总览或每日快照返回 `{"data": {...}}`；目录返回 `{"items": [...], "total": 1}`。
业务列表返回如下结构（空列表示意，实际快照编号由服务端生成）：

```json
{
  "schema_version": "1.2",
  "source_schema_version": "3.0",
  "strategy_id": "strategy_1",
  "strategy_name": "策略1",
  "trade_date": "2026-09-04",
  "snapshot_id": "snap_example",
  "updated_at": "2026-09-04T15:00:00+08:00",
  "currency": "CNY",
  "timezone": "Asia/Shanghai",
  "execution_kind": "shadow_simulation",
  "items": [],
  "total": 0,
  "page": 1,
  "page_size": 50
}
```

- `schema_version` 是公开接口结构版本，和业务实现版本无关；`source_schema_version` 是原始业务快照结构版本。
- `page` 从1起，`page_size` 默认50，最大200；`total` 是筛选后的总数。
- 股票代码 `code` 为六位字符串，必须保留前导零。股票名称是证券名称，不是策略名称。
- 金额均为人民币元；价格为元/股；股数为股。不要把金额直接当成“万元”。
- 所有 `*_return` 都是小数比率，展示百分数时乘100；例如0.0123显示为1.23%。
- `null` 表示数据不可得，展示“—”，不要替换成0。空列表表示该快照没有相应记录。
- 日期时间使用 ISO 8601，中国时区为 `+08:00`；补录计算时间可以晚于行情日期。
- `snapshot_id` 是不透明的快照标记。`signal_id`、`event_id` 也不应解析或拼装。
- 信号按 `signal_at` 倒序，成交按 `execution_at` 倒序，平仓按 `exit_execution_at` 倒序；
  时间相同按代码升序。观察与持仓按代码升序。收益曲线按交易日升序。

## 总览

`overview.data` 除共用字段外，还包含 `strategy`、`status`、`recording`、`runtime`、
`summary`、`observation_summary`、`signal_summary`，以及 `selection_date`、`generated_at`、
`execution_rule`、`timeline`。

策略目录项只有 `id`、`name`、`execution_kind`；总览中的 `strategy` 还提供计算参数，详见下文。
当前 `execution_kind` 固定为
`shadow_simulation`，页面应显示“模拟成交”或“模拟账户”。使用真实行情不等同于券商实盘成交。

`status`：`waiting_open`（待开盘）、`monitoring`（运行中）、`closed`（已收盘）、
`error`（异常）、`unknown`（状态未知）。行情完整性以 `runtime.data_status` 为准。

`recording`：

| 字段 | 含义 |
| --- | --- |
| `start_date` | 连续账户起点，当前为2026-08-20 |
| `mode` | `historical_replay`：真实历史行情补录；`live`：实时运行；`unknown`：未注明 |
| `market_data_trade_date` | 使用的行情交易日期 |
| `computed_at` | 实际计算时间，不是成交时间 |
| `data_kind`、`strategy_version` | 行情数据类型、业务版本 |
| `execution_kind` | 当前为 `shadow_simulation` |

`runtime`：`version`（快照计数）、`evaluated_at`（快照计算参考时点）、
`last_valuation_at`（最近估值刷新时间，如有）、`data_status`、`incomplete_code_count`、
`incomplete_codes`。同时提供 `schema_version`、`mode`、`last_complete_bar_at`、`next_evaluation_at`、
`expected_complete_bar_count`、`bars_per_complete_day`、`observation_count`、`complete_observation_count`、
`incomplete_observation_count`、`tracked_code_count`、`source`、`preparation_quality`、`resource_limits`、
`observation_state_counts`、`last_error`、`last_error_at` 和 `data_status_detail`。快照是否变化以 `snapshot_id` 为准；不能只依赖 `version`。

`data_status` 对外只使用：`waiting_open`、`waiting_data`、`fresh`、`partial`、`closed`、
`closed_partial`、`error`、`unknown`。`partial`/`closed_partial` 表示数据不完整，仍可能有
可展示的数据；持仓各自的估值时点看 `marked_at`。`last_error` 提供已匿名真实名称的错误说明，可在详情中展示；外层HTTP服务错误仍使用通用提示。

`summary` 字段：

| 分类 | 字段 | 展示含义 |
| --- | --- | --- |
| 账户 | `account_count`、`initial_capital` | 曾买入账户数、这些账户的累计初始本金 |
| 资产 | `cash_balance`、`market_value`、`total_assets` | 现金、持仓市值、总资产 |
| 累计收益 | `total_pnl`、`total_return` | 起点至该快照累计盈亏、总收益率 |
| 收益组成 | `realized_pnl`、`unrealized_pnl` | 累计已实现盈亏、当前持仓浮盈亏 |
| 当日收益 | `account_day_pnl`、`account_day_return` | 剔除新增本金后的当日盈亏；收益率分母为日初资产＋当日新增本金 |
| 新增本金 | `new_account_count`、`capital_inflow` | 当日首次买入账户数、这些账户首次纳入的本金 |
| 统计范围 | `universe_account_count`、`inactive_account_count` | 内部固定股票账户池数量、从未买入且不计入金额的账户数量 |
| 当日分母 | `opening_total_assets`、`account_day_return_base` | 日初已交易账户资产、当日收益率实际分母 |
| 当日成交额 | `buy_notional`、`sell_notional`、`turnover` | 买入金额、卖出金额、买卖金额之和，均不含费用 |
| 当日费用 | `total_fees`、`net_cash_flow` | 成交费用合计、成交导致的现金净变动 |
| 观察与信号 | `observation_count`、`preselection_count`、`signal_count` | 当前观察数、当日预选数、信号记录数 |
| 信号进度 | `pending_signal_count`、`rejected_signal_count` | 当前待成交、当日未执行记录数 |
| 当日笔数 | `buy_count`、`sell_count`、`closed_trade_count` | 买入成交、卖出成交、平仓交易笔数 |
| 持仓数量 | `holding_count`、`t1_locked_holding_count` | 持仓股票数、当日不可卖持仓数 |

每只股票仍有独立的100,000元初始可用资金。只有首次买入真实模拟成交后，该股票账户才进入公开汇总；
观察、待成交、被拒绝和从未买入的账户不计入本金、现金、资产及收益率。已清仓账户继续计入，保留已实现盈亏和现金；
再次买入不会重复计入10万元本金，账户资金也不会补回10万元。
`return_basis="traded_accounts_initial_capital"`，总收益率=累计盈亏/截至该日曾买入账户的初始本金之和。
每个历史快照只使用截至当日已发生的买入，不能用最后一天的账户集合回填过去。
`account_day_return_basis="opening_assets_plus_capital_inflow"`；当日新增本金不是盈利，日收益分母为日初资产＋新增本金，未做盘中资金流时间加权。
没有任何成交时，汇总本金、现金、资产、盈亏和收益率均为0，前端可展示“尚未买入”。费用已计入盈亏，不要重复扣除。

```text
total_assets = cash_balance + market_value
total_pnl = total_assets - initial_capital
total_return = total_pnl / initial_capital（分母为0时返回0）
account_day_pnl = total_assets - opening_total_assets - capital_inflow
account_day_return_base = opening_total_assets + capital_inflow
account_day_return = account_day_pnl / account_day_return_base（分母为0时返回0）
turnover = buy_notional + sell_notional
net_cash_flow = sell_notional - buy_notional - total_fees
```

`observation_summary` 包含 `count`、通用状态 `state_counts` 和细分状态 `detail_state_counts`。
`signal_summary` 包含 `count` 与 `recent_items`，最近记录和信号分页使用相同字段。

## 观察与信号

观察基础字段：`code`、`name`、`action`、`state`、`data_status`、`signal_id`；
还返回 `state_detail`、`data_status_detail` 以及下文列出的指标、判断原因和确认进度。
`action` 为 `buy`（买入观察）、`sell`（卖出观察）、`hold`（持仓观察）。
观察并不表示已形成可执行信号；同一股票只在自己的策略账户内产生影响。

| 观察 `state` | 页面文案 |
| --- | --- |
| `watching` | 观察中 |
| `holding` | 持仓观察 |
| `signal_confirmed` | 已产生信号 |
| `pending_execution` | 待成交 |
| `filled` | 已模拟成交 |
| `rejected` | 未执行 |
| `not_triggered` | 未触发 |
| `unknown` | 状态待更新 |

信号项字段：`signal_id`、`code`、`name`、`action`、`status`、`signal_at`、`signal_price`、
`execution_at`、`execution_price`、`shares`。买卖方向为 `buy`/`sell`。
`status` 为 `pending_execution`、`filled`、`rejected`、`cancelled`、`unknown`。
未成交时成交时间、成交价格、股数可能为空；成交金额与费用以成交接口为准。

v1.1保留通用 `status`/`state` 兼容已有页面，另外完整提供 `status_detail`/`state_detail`、
`reason`、参数与指标、确认进度和执行尝试。不要再按v1.0的隐藏规则删掉这些数据。
接口不提供未计算的评分；不存在的数据不应由前端编造。
不要用信号价格乘股数自行代替成交金额；信号形成与成交是不同事件。

## 成交、持仓和平仓

`executions` 每项字段：

| 字段 | 含义 |
| --- | --- |
| `event_id`、`code`、`name` | 公开成交标识与股票 |
| `action`、`status` | 买/卖；成交状态通常为 `filled` |
| `signal_at`、`signal_price` | 对应信号时点和价格 |
| `execution_at`、`execution_price`、`shares` | 模拟成交时间、价格、股数 |
| `notional` | 成交金额，不含费用 |
| `commission`、`stamp_duty`、`total_fees` | 佣金、印花税、两者合计 |
| `cash_flow` | 买入为负支出，卖出为扣除费用后的正收入 |

`holdings` 每项字段：

- 身份与数量：`code`、`name`、`shares`、`entry_event_id`；
- 建仓：`entry_execution_at`、`entry_execution_price`、`entry_notional`、`buy_commission`；
- 成本：`cost_basis = entry_notional + buy_commission`；
- 估值：`marked_at`、`mark_price`、`previous_close`、`market_value`；
- 累计浮盈亏：`unrealized_pnl`、`unrealized_return`，已扣买入费用；
  `total_pnl`、`total_return` 为同口径别名，单笔收益率分母是该持仓含费成本；
- 标的当日变化：`market_day_pnl`、`market_day_return`，相对前收盘价；
- 账户当日变化：`account_day_pnl`、`account_day_return`，今日买入相对含费成本、
  隔夜持仓相对前收盘价对应的持仓价值；
- 可卖状态：`sellable_today`、`t1_locked`。

`closed-trades` 是所选交易日完成的平仓，不是从起点累计的所有平仓。每项字段：
`code`、`name`、`shares`、`entry_event_id`、`exit_event_id`、
`entry_execution_at`、`exit_execution_at`、`entry_execution_price`、`exit_execution_price`、
`entry_notional`、`exit_notional`、`buy_commission`、`sell_commission`、`stamp_duty`、`total_fees`、
`gross_pnl`、`net_pnl`、`net_return`。其中费用包含买卖佣金与卖出印花税，
`net_pnl` 为扣完上述费用后的盈亏，`net_return` 的分母为含买入费用的建仓成本。

## 参数、指标与详细判断

总览 `strategy` 除匿名身份外，包含：`version`、`macd_parameters`、`intraday_interval`、
`minimum_shrink_ratio`、`confirmation_bars`、`buy_filter`、`exit_policy`、`recording_start_date`。
这些计算信息允许展示，但不要据此拼出或替换策略的真实名称。

`execution_rule` 包含模拟成交约定：`mode`、`initial_cash_per_stock`、`slippage_rate`、
`commission_rate`、`stamp_duty_rate`、`lot_size`、`settlement`、`price_limit`。
`timeline` 每项为 `stage`、`status`、`at`，记录选股、监控、收盘等事件。
补录的真实计算时间和行情事件时间可能不按数组顺序递增，勿自行改写时间。

信号与观察共同增加：

| 字段 | 含义 |
| --- | --- |
| `reason` | 判断或执行状态说明，仅真实策略名称已替换 |
| `observation_before_date`、`observation_date` | 观察参考日期 |
| `reference_histogram` | 参考柱值 |
| `provisional_dif`、`provisional_dea`、`provisional_histogram` | 当前临时指标值 |
| `shrink_ratio` | 柱值收缩比例 |
| `adx_14`、`adx_14_3_days_ago` | 当前已完成日与比较日的指标值 |
| `factor_completed_date`、`factor_comparison_date` | 指标实际对应的日期 |

观察独有明细：`condition_met`、`consecutive_confirmations`、`required_confirmations`、
`last_complete_bar_at`、`adx_buy_allowed`、`adjustment_factor`、`exit_state`。
可以展示“当前满足/未满足”“确认次数/要求次数”，但不将观察进度当成已经成交。

信号独有明细：`minimum_shrink_ratio`、`confirmation_count`、`execution_reference_price`、
`attempt_count`、`attempts`、`exit_reason`、`deferred_from`、`estimated_net_return`。
`attempts` 每项包含 `attempt_at`、`execution_bar_end_at`、`reference_open`、`daily_price_limit`、
`status`、`reason`。这是后端保存的有限长度尝试记录；`attempt_count` 是总尝试次数，
可能大于 `attempts.length`，不要把后者当成累计尝试次数。

细分状态及推荐文案：

| 明细状态 | 含义 |
| --- | --- |
| `confirming` | 连续确认中 |
| `deferred_exit` | 延期退出、继续持有 |
| `rejected_adx` | 趋势条件未通过 |
| `rejected_limit_up` | 涨停未执行买入 |
| `rejected_insufficient_cash` | 独立账户资金不足 |
| `deferred_t1` | 当日买入不可卖，等待后续执行 |
| `deferred_limit_down` | 跌停暂不可卖，等待后续执行 |

`status_detail`/`state_detail` 为原始细分状态字符串，未列出的值也应能显示原值或通用文案。
查询例：`signals?status_detail=rejected_adx`、`observations?state_detail=confirming`。
通用状态筛选保持原枚举，两种筛选同时传入时取交集。
数据原因为 `missing_previous_close` 等细分值时，通过 `data_status_detail` 保留。

成交补充字段：`reason`、`execution_reference_price`、`execution_price_source`、`previous_close`、
`daily_price_limit`、`execution_bar_low`、`execution_bar_high`、`slippage_rate`。
完整快照的 `intraday_trading.interval` 提供所用周期。

持仓补充字段：`entry_signal_at`、`entry_signal_price`、`entry_reference_price`、
`gross_total_pnl`、`gross_total_return`。毛盈亏不扣买入费，净盈亏扣买入费，两者分母也对应不同成本。
平仓补充字段：`entry_signal_at`、`exit_signal_at`、`entry_signal_price`、`exit_signal_price`、
`entry_reference_price`、`exit_reference_price`。

总览汇总还提供：`watching_count`、`not_triggered_count`、`sell_candidate_count`、`realized_return`、
`gross_unrealized_pnl`、`gross_unrealized_return`、`unrealized_return`、`holding_market_day_pnl`、
`holding_market_day_return`、`open_position_account_day_pnl`、`open_position_account_day_return`、
`closed_position_account_day_pnl`、`closed_position_account_day_return`、`return_basis`。
这些保留后端各自口径；不要混用毛收益、净收益、持仓收益和全账户收益。

## 逐股账户、候选与退出记录

`accounts` 只返回截至所选日期曾经买入过的账户，包含当前持仓和已经清仓者；从未买入者不返回。
支持 `has_position=true|false`，其中false表示已买入过但当前清仓，不表示从未参与。
每项：`code`、`name`、`initial_capital`、`cash_balance`、`market_value`、`total_assets`、
`realized_pnl`、`unrealized_pnl`、`total_pnl`、`total_return`、`has_position`、`shares`、`marked_at`、`first_buy_at`、`has_traded`。
单账户收益率以该股初始本金为分母，与单笔持仓成本收益率不同。
账户数据与总览可以按以下关系对账：

```text
单股 total_assets = cash_balance + market_value
单股 total_pnl = total_assets - initial_capital
单股 total_return = total_pnl / initial_capital
全部账户各金额字段之和 = 总览相应金额字段
```

该接口额外返回 `available`：无逐股账本的旧快照为false，不能理解为真实账户数为0。
`has_position`、市值及盈亏为null表示持仓或估值数据不足，不能当作空仓或0盈亏。
账户数量按所选日期的响应读取。2026-09-04计入136个，其中持仓130个、已清仓6个；内部固定池5,541个只作为股票覆盖信息，不参与汇总金额。

`preselections` 和 `sell-candidates`：每项 `code`、`name`、`reason`、`reference_price`、`status`；
卖出候选未记录状态时为null。候选不代表已买入或卖出。

`exit-decisions`：每项 `code`、`name`（未记录时为null）、`at`、`entry_at`、`state_before`、
`state_after`、`action`、`reason`、`original_sell`、`deferred_from`、`adx_state`、`adx`、
`adx_3_days_ago`、`factor_completed_date`、`provisional_dif`、`provisional_histogram`、`allow_delay`、
`data_anomaly`、`quote_price`、`quote_net_proceeds`、`entry_cost`、`estimated_net_return`。
判断记录不是成交记录；收益估算也不是已实现收益。它返回后端实际保存的记录，不承诺每次检查都保存。
列表按 `at` 倒序，同时间按代码排序。

完整每日快照新增 `accounts`、`preselection_pool`、`sell_candidate_pool`、`exit_decisions`；
各池包含 `count`、`items`，`accounts` 额外包含 `available`。
数据量较大，前端日常按分页接口和详情抽屉按需请求，不要每次轮询都下载全部账户与明细。

## 收益曲线和一致性

`performance` 返回 `strategy_id`、`strategy_name`、`items`、`total`、`page`、`page_size`。
每个点包含共用快照字段、`recording`、`runtime`、`summary`。
前端用 `trade_date` 作横轴，收益曲线优先展示 `summary.total_pnl` 和 `summary.total_return`。
`total_return` 是累计盈亏/动态纳入本金，新增账户会改变分母，不是日收益连乘得到的时间加权净值。
若展示 `summary.total_assets` 资产曲线，必须同时展示本金线 `initial_capital` 或标注 `capital_inflow`，不得将新增本金造成的资产增长标为盈利；
当日快照未收盘时展示为盘中点，不当作最终收盘值。获取超过200个交易日时应翻页。

推荐加载顺序：

1. 从目录获取公开策略编号，加载 `overview`。
2. 携带总览的 `trade_date` 和 `snapshot_id` 请求列表，按需加载分页。
3. 请求 `performance` 绘制收益曲线；它是各交易日独立快照序列。
4. 刷新总览后，仅当 `snapshot_id` 变化时重载当前列表。分页返回409时清理旧页，重取总览。

服务端不保留任意旧快照版本；`snapshot_id` 是一致性校验，不是历史版本查询参数。
如需同一响应内的全部模块，可使用 `daily-results/{trade_date}`，其全部列表不分页。

常见状态码：200成功；404策略或日期没有数据；409快照变化；422参数错误；503数据服务暂不可用。

账户从8月20日空仓、每股10万元开始，股票池按8月19日已知股票冻结。
9月3日、9月4日已按同一起点重新计算，原两日快照已备份；旧起点的收益不可与新曲线拼接。

`recording.reference_price_method` 标注前收盘参考价的来源策略：优先用采集值，缺失时只采用

## 成交区间查询与日K标记（v1.2兼容扩展）

现有`GET /api/v1/quant/strategies/strategy_1/executions`与短路径`GET /api/v1/quant/executions`同时支持：

```text
/executions?code=000036&start_date=2026-08-20&end_date=2026-09-04&page=1&page_size=100
/executions?code=000036&trade_date=2026-09-01
```

### 请求规则

- 不传区间：保留原来的单日行为。`trade_date`省略时查询最新已有交易日。
- 传区间：`start_date`和`end_date`必须同时提供，首尾日期均包含；不能与`trade_date`混用。
- `code`为6位字符串（保留前导0）；可与`action=buy|sell`一起筛选，也可省略代码读取区间全部成交。
- `page`从1开始；`page_size`默认50，最大200。`total`是筛选后的成交笔数，不是交易日数。
- 排序为成交时间倒序；同时间按股票代码、来源日期及事件标识稳定排序。K线组件如需正序自行排序。
- 参数不完整、日期倒置、混用单日/区间或分页越界返回422；未知策略404。
- 有效区间没有记录/该股票没有成交/页码超过末页，返回200与`items=[]`，保留真实`total`。原单日查询无快照仍返回404。
- 区间读取`quant_daily_results`已保存成交，不重新运行策略、不改账户数据，也不会自动加入独立的六月研究档案。当前正式记录起点仍为2026-08-20。

### 版本与翻页

返回沿用`items/total/page/page_size/strategy_id/strategy_name/currency/timezone/execution_kind`，新增：

|字段|含义|
|---|---|
|`query_mode`|`single_day`或`date_range`|
|`code`、`action`|请求筛选条件；未指定为null|
|`start_date`、`end_date`|查询的首尾日期；单日模式二者均为实际查询日|
|`trade_date`|单日保持原日期；区间为null，不能用它给所有成交打日期|
|`history_version`|当前查询范围、代码、方向及区间全部日快照修订信息的不可解析版本号；与页码、每页数量无关|
|`snapshot_id`|单日保持与overview一致；区间与history_version相同，代表区间版本|
|`history`|下面列出的历史范围和重算元数据|

`history`包含：

- `covered_start_date`、`covered_end_date`、`trade_day_count`：请求区间内实际存在的日快照覆盖，不等于该股票成交日期范围；无记录时首尾为null、天数为0。
- `recording_start_dates`、`recording_modes`、`strategy_versions`：区间实际包含的记录起点、`historical_replay/live`模式和业务版本集合；`strategy_versions`不是历史重算版本。
- `computed_at`、`history_rebased_at`、`accounting_rebased_at`：区间内各字段最近的已记录时间；这些都不是成交时间。不同日期可能有不同时间，每笔的`recording`保留其来源日详情。
- `incomplete_trade_dates`：来源日数据状态不是fresh/closed的日期，应保留数据不完整提示。

前端第一页不传版本，拿到`history_version`后，在同一股票、区间和方向的后续分页中原样回传。
任何一天（包括没有成交的日期）重新计算、修订或新增/删除日快照，均会改变区间版本。版本不符返回409：丢弃该查询已加载的所有页，从第一页重新获取，不能把新旧页拼接。
切换股票、区间、方向时清空版本和旧请求结果；旧范围的history_version不能复用。
区间请求可用`snapshot_id`作同等检查，但不能把单日overview的snapshot_id用于多日查询。
即使latest日期的版本不变，更早日期重算也会更新history_version。不能只比较最后一天更新时间。

### 每笔成交和价格口径

每条`items[]`在原有成交时间、价格、数量、金额、费用等字段外，还包含：

```json
{
  "trade_date": "2026-09-01",
  "snapshot_id": "snap_来源日版本",
  "execution_kind": "shadow_simulation",
  "marker_type": "simulated_execution",
  "price_basis": "recorded_execution_price",
  "recording": {
    "mode": "historical_replay",
    "strategy_version": "2.0.0",
    "computed_at": "对应来源日的计算时间",
    "history_rebased_at": "对应来源日的历史重建时间",
    "accounting_rebased_at": "对应来源日的账户口径更新时间"
  }
}
```

以上为字段示意，真实响应样例见`量化前端响应示例.json`中的`executions_range`及`executions_range_page_2`。
每笔`snapshot_id`是来源单日版本，与同一天单日接口一致，不要与外层区间snapshot_id混淆。

- `/executions`仅返回`status=filled`的模拟成交，默认标记文字用“模拟买入/模拟卖出”。
- `execution_price`为当时成交记录原值，包含当时撮合滑点；没有按当前K线前复权系数换算。
- `price_basis=recorded_execution_price`明确其为记录价格，不承诺等同当前前复权K线价格，也不要自行反推复权后成交价。
- 日K用前复权价格时，按每笔`trade_date`定位K线，买入标记放该K线下方、卖出标记放上方；详情展示原始模拟成交价、成交时间、数量、金额、手续费及模拟成交性质。
- 不能用`computed_at/history_rebased_at/accounting_rebased_at`定位标记，也不能将所有区间成交定位在外层trade_date。
- 未成交信号继续读`/signals`，用独立样式和“未成交”文字；不得把信号价画成成交标记。
- 缺少对应日期K线时保留成交详情，标记无法定位，不要移到相邻交易日。
