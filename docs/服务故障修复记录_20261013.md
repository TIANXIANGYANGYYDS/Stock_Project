## 根因及代码修复

东方财富股票清单请求断开，导致日线同步在创建任务记录之前退出。10 月 12 日日线完全缺失，量化建账依赖断裂；10 月 9、12、13 日仅留下错误占位文档，没有账户起点。后续量化又把前序错误占位文档当成旧策略账本，无法继续恢复。

- 股票清单请求改用项目已有的 curl_cffi 异步浏览器 TLS 客户端，保留独立代理连接和数据校验。线上股票清单请求恢复成功。
- 清单阶段失败也持久化失败运行记录，进入补偿流程；过去交易日依据该日实际采集的有成交分钟数据确定补录股票范围，避免误用今天的实时清单。
- 日线补偿覆盖“没有留下运行记录”的历史故障，新增当日 16:00 补偿；主任务失败向调度器传播异常。
- 量化按交易日历逐日检查连续性，等待日线成功后恢复。严格区分错误占位文档和真实旧策略账本，不跳过缺失交易日。
- 开盘准备、分钟刷新和收盘后恢复均可接续历史账本；新增 16:15、17:15、18:15 恢复调度。
- 分钟库已完成迁移后不再启动时扫描全表；行情质量查询增加覆盖元数据的索引，并限制查询执行时间。索引已在正式库创建。
- 乱序和累计量回退仍执行原有保护，告警改为每轮汇总计数，减少逐股票重复日志；这项改动没有消除行情源本身的质量问题。

## 尚未解决的独立问题

1. **系统授时**：`NTPSynchronized=no`，chrony 没有可用授时源；程序测得 HTTP 时钟偏移约 -300.9 秒。当前用户没有免密 sudo 权限，无法修改系统时间或 chrony 配置。需要管理员恢复可用授时源并校准主机；这是当前分钟完整性判断和定时任务触发时刻仍有偏差的重要因素。
2. **博主上游会话**：三个抖音账号请求返回 HTTP 403；微博第一页可读取、后续页返回 `ok=-100`，没有完成覆盖。需要恢复平台认可的登录会话或处理账号访问限制。Cookie 本地过期检查正常不足以证明平台接受请求；本次没有伪造成功状态或绕过平台限制。
3. **历史质量和存量任务**：既有 10 月 8 日账本 `closed_partial`、历史分钟缺口和旧失败队列仍保留。今天 worker 成功不意味着旧任务已全部补做。没有批量清空失败记录、改写旧账本或重跑全部历史 LLM 任务。
4. **资源及退出日志**：磁盘此前使用率约 91%；已减少行情重复日志，但没有删除历史业务数据。旧调度器退出时出现一次关闭 MongoClient 后仍尝试持久化的异常，新进程启动后的核验未复现运行期异常；优雅退出顺序可另行修正。
