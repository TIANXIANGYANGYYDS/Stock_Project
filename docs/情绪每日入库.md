# 策略二：每日情绪数据留存

策略二目前留存市场事实，供后续重新设计短线情绪策略。日常链路只做收盘采集、统计和入库。正式股票服务及策略一的集合不参与本次调整。

## 两张表的职责

两张表均为**一个统计范围、一个交易日一条文档**，唯一索引为 `(scope, trade_date)`；当前 `scope=hs_mainboard`、`version=daily-observation-v2`。`version` 记录口径版本，不参与唯一键，同一天不因升级产生多份正式记录。

| 集合 | 职责 | 长期留存内容 |
| --- | --- | --- |
| `market_sentiment_daily` | 回答“当天市场表现如何” | 基础统计、缺失原因、输入质量和入库时间 |
| `market_sentiment_raw_daily` | 回答“统计依据是什么、涉及哪些股票” | 当日名单、逐股不复权行情、状态和限价、涨停股连板高度、数据来源和输入哈希 |

不新增选股池表、订单表、资金账户表或实验结果表。离线研究仍可读取原始依据，自行计算评分和周期。

### 每日汇总 `market_sentiment_daily`

| 字段 | 内容 |
| --- | --- |
| `scope / trade_date / version` | 统计范围、交易日期和口径版本 |
| `values` | 下表列出的 41 个基础统计字段；缺失值为 `null` |
| `missing_reasons` | 仅为缺失字段保存原因，不把未知当成 0 |
| `quality` | 原始名单家数、应统计家数、各类排除数量、价格错误统计、退市状态未知家数 |
| `recorded_at` | 首次入库时间 |

| 指标组 | `values` 字段及含义 |
| --- | --- |
| 涨跌停与梯队 | `limit_up / limit_down` 涨跌停家数；`board_1`～`board_9`、`board_10_plus` 连板梯队；`unknown_streak` 高度未知家数；`chain_count` 已知 2 板以上家数；`height / previous_height` 今日、昨日最高板 |
| 市场广度 | `advancing / declining / flat` 红绿平盘家数；`up_over_5 / down_over_5` 涨跌超 5% 家数，剔除对应涨跌停；`drawdown_8` 收盘较最高价回撤至少 8% 的家数 |
| 涨跌停形态 | `broken` 触涨停但未封住家数；`seal_rate` 收盘涨停家数 / 触涨停家数；`one_word` 四价均为涨停价；`floor_to_ceiling / ceiling_to_floor` 日线触跌停且收涨停 / 触涨停且收跌停代理 |
| 昨日股票反馈 | `yesterday_up_return / yesterday_chain_return` 昨涨停 / 昨 2 板以上股票今日涨幅中位数；`consecutive_down` 连续两日跌停家数；`high_loss` 昨 4 板以上股票今日跌超 5% 家数 |
| 晋级率 | `promotion` 昨涨停晋级；`chain_promotion` 昨 2 板以上晋级；`one_to_two / two_to_three` 一进二、二进三；`high_promotion` 昨 3 板以上晋级 |
| 成交额 | `amount` 有效统计池成交额，亿元；`amount_ratio` 当日成交额 / 此前 20 个交易日成交额中位数，不含当日 |
| 覆盖情况 | `coverage` 有效统计家数 / 应统计家数；`eligible` 有效统计家数；`missing` 缺失或无效家数 |

比例和涨幅使用小数，例如 `0.64` 表示 64%，`-0.02` 表示 -2%。股票价格为元，原始 `amount_yuan` 为元，`volume_shares` 为股。汇总的 `amount` 是沪深主板有效统计池成交额，不是全 A 成交额。

### 逐股依据 `market_sentiment_raw_daily`

| 字段 | 内容 |
| --- | --- |
| `scope / trade_date / version` | 与汇总相同的身份及口径版本 |
| `market.expected_codes` | 当日应观测的主板名单，不能用今天的名单替换历史名单 |
| `market.stocks[]` | 股票代码、不复权 OHLC、可比昨收、成交额/量、ST/停牌/退市状态、是否限价、涨跌停价及原始来源信息 |
| `market.universe_source / universe_known_at` | 名单来源和已知时间；不能核实时保留未知 |
| `limit_streaks` | 当日可识别涨停股票的 `{代码: 连板高度}`，未知高度保留 `null`；包含可观测但被市场统计排除的股票，避免身份变化时丢失连续性 |
| `provenance` | 供应商、采集或补录方式、原始文件位置、观测时间和数据假设；仅此表保存完整来源 |
| `input_hash` | 对原始 `market` 的 SHA-256 校验值 |
| `recorded_at` | 首次入库时间 |

保留每日打包方式，避免把已有 318 日依据拆成约百万条逐股文档并增加索引。连板高度属于逐股计算结果，与 `market` 原始输入分开保存；`input_hash` 不包含它。日表与依据表通过 `(scope, trade_date)` 关联。

## 删除和合并的内容

- 删除 `market_sentiment_state`：不再保存整套引擎检查点、研究因子窗口、周期状态和 MongoDB 租约。
- 删除 `market_sentiment_runs`：任务成功和失败沿用现有调度日志，不再单独建业务表记录每次运行。
- 日表删除 `model`、`values.emotion`、`values.phase` 和恒定的 `signal_usable`；研究评分和四阶段模型留在离线研究中。
- 日表删除重复的 `source`、`input_hash`、`result_hash`，删除与 `values` 重复的质量计数和研究专用覆盖指标。
- 删除服务端为旧界面准备的指标分组、显示标签注册表，字段口径以本文为准。

## 采集与恢复

1. 读取最近 20 日汇总和最后一个完成日的逐股依据，恢复昨日股票特征及连板高度。
2. 按供应商交易日历逐日补齐已收盘日期，计算基础统计。
3. 先写当日依据，再写当日汇总；**汇总存在表示该日已经完成**。
4. 如果只写了依据就中断，重跑时复用已存依据完成汇总；无需额外检查点表。

同日同内容重复执行不新增记录；输入、连板高度或统计结果不同则拒绝静默覆盖。修改统计口径需要明确迁移并从原始依据重算。

当前是单机部署，所有写入走 CLI 的进程文件锁 `.local/market_sentiment/record.lock`，进程退出即释放。调度器和手工命令共用该入口。文件内容不保存计算状态，也不参与数据恢复；未来多机部署需重新设计写入互斥。

APScheduler 任务 `market_sentiment_daily` 在北京时间工作日 **18:30、20:30、22:30** 触发，使用交易日历跳过休市日。15:30 前不采集当日；供应商未就绪或有效覆盖不足 98% 时等待补采。无需重启股票查询服务或策略一。

```bash

```

首次也可从已有研究底稿补录：

## 数据边界

- 统计范围为沪深主板，排除 ST、停牌、已识别退市整理及无涨跌幅限制股票。
- 使用 BaoStock 不复权价格和可比昨收，不能用原有前复权行情直接替代涨跌停依据。限价含常规规则重建，特殊制度和退市状态尚未完整核验。
- 昨日股票反馈固定使用昨日名单；今日变 ST 的昨日赢家仍参与反馈，停牌或缺行情则留空，不缩小分母。
- 日线只能提供触板与收盘代理，不能确认盘中先后顺序、封板时长和排队成交。
- 历史补录时间不冒充历史公开时间。保留原数据假设，迁移不提高数据可信等级。
