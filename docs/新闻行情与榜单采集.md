# 新闻、行情与榜单采集（2026-10-16）

本次仅调整采集、归档和调度，不修改量化账本。入口仍是现有 scheduler，新增榜单先提供 MongoDB 数据，不增加前端路由。

## 当前链路

| 业务 | 获取与频率 | 落库 |
|---|---|---|
| 金十新闻 | 每 3 分钟读取官方 `flash_newest.js`，失败才尝试原 HTML 路径 | `news_data`，`source=jin10`，按稳定快讯 ID 去重 |
| 股票实时行情 | 原有 5 秒轮询；腾讯 → 新浪 → 东方财富批量兜底 | 原有实时报价归档、竞价归档及分钟行情集合 |
| 同花顺热股前 100 | 交易日 09:30–11:30、13:00–15:00，每 5 分钟采样 | `stock_ths_hot_rank_snapshots` |
| 每日股票龙虎榜 | 交易日盘后每 15 分钟检查当日漏采；每轮最多尝试 3 次，已有成功日档则跳过；启动补查 | `stock_billboard_daily` |
| 榜单执行状态 | 每次实际抓取成功或失败时记录 | `market_observation_runs` |

交易日由项目已有 A 股交易日历判断，节假日和午休不采热股榜。热股任务在主机上预留较宽的触发窗口，业务层用校准时间严格检查交易时段。同一五分钟时段成功后不再重复保存；恢复启动只抓当前时段，不生成错过的历史快照。

## 实时行情兜底与质量边界

1. 腾讯正常时使用原有批量请求。缺失、时间过旧、未来时间、无价格及相对上一批已接受报价发生时间回退时，向新浪请求对应股票。
2. 新浪仍缺失或无效，或新浪报价缺少可验证的涨跌停价时，进入东方财富备用请求。每轮最多选 200 只，轮换处理超额股票。
3. 东方财富使用 `ulist.np/get` 批量报价，并用 `stock/get` 补取最多两只股票的日内涨跌停价；总时限 3 秒。部署已有代理时使用现有 51 代理，代理失败后弃用；没有配置代理时允许直连。网络失败和未处理股票都有质量指标。
4. 仅同一个交易日、相同昨收价、价格落在限价内时复用已验证的静态涨跌停价。字段 `limit_source`、`limit_source_time`、`limit_raw_fields` 保留证据。不会从旧报价沿用实时价格、成交量、盘口和来源时间，也不按固定涨跌幅猜限价。
5. 原始响应字段和被拒绝的报价继续归档。`validation_issue=out_of_order` 会转成归档 `quality_issue`；所有消费端继续遵守有效性校验。新增指标 `usable_with_daily_limits` 区分普通有效报价与具备限价字段的报价。

东方财富备用数据没有在本次实现中提供已验证盘口，盘口保持空；不能用它推算封单或制造回封事件。停牌、零价、过期和上一交易日报价不会因兜底而重新有效。五秒快照也不保证捕获采样间隙内的全部交易事件。

主机目前仍存在约 +305 秒时钟偏差，NTP 尚未同步。本次复用两个 HTTPS 来源一致性校时；校时失败时新增榜单任务报错，不拿无法验证的时间发布定时快照。`fetched_at` 是主机实际接收时间，`observed_at` 是校准后的观察时间，`clock_offset_seconds` 保存补偿值；来源报价时间单独保留。应用校准不等同于修复主机授时。

## 榜单数据结构

### 同花顺热股快照

来源为同花顺公开 `hot_stock/a/hour/data.txt`，使用源站的 `order` 和 `rate`，不自行计算排名或热度。`hour` 是所用上游榜单路径，五分钟是本服务采样频率，不能据此保证上游也每五分钟更新。

每份文档必须包含排名 1–100 且不重复的 100 只股票，否则整份拒绝保存。

```text
_id                    交易日:HH:MM；手动验证使用 manual:实际时间
trade_date             采集观察所属日期
scheduled_slot         校准后的五分钟时段；手动抓取为 null
observed_at/fetched_at  校准观察时间 / 主机接收时间
clock_offset_seconds   时钟补偿秒数
source/source_url      THS / 实际来源地址
rank_type              hour
source_time            null（接口未提供榜单生成时间，不能用抓取时间替代）
source_http_date       HTTP Date，仅作传输时间证据
source_last_modified   如源站提供则保留，否则 null
run_mode               scheduled 或 manual
stocks[]               rank、code、name、heat、rank_change、raw
```

盘后手动验证也保留实际时间并标记 `manual`，不写成当天 15:00 或任何缺失的盘中时点。

### 龙虎榜日档

从东方财富数据中心分别读取股票上榜汇总、买入席位、卖出席位；按接口总页数遍历，校验总行数和日期，以股票代码、披露 ID 关联。同一股票的不同上榜原因保留多条记录。多个“机构专用”席位不能只按名称去重。席位源额外返回的可转债不混入股票龙虎榜。

```text
_id/trade_date          YYYY-MM-DD
source/source_url      EASTMONEY / 数据中心接口
observed_at/fetched_at  同上
record_count           上榜记录数（可能大于股票数）
stock_count            不重复股票数
report_counts          三个来源报告各自的行数
publication_status     observed
is_exchange_final      false
records[]              code、disclosure_id、name、reason、market、close、change_pct、
                       buy_amount_yuan、sell_amount_yuan、net_amount_yuan、
                       buy_seats[]、sell_seats[]、raw
```

金额单位为人民币元，`change_pct` 为百分数，例如 `-10` 表示 -10%。席位保留源站完整字段，`BUY/SELL/NET` 是元；`TOTAL_BUYRIO/TOTAL_SELLRIO` 是源站比例。披露内容可能是多日累计，读取 `reason` 判断，不能统一解释成当天逐笔成交。

16:00 的数据是当时源站已披露的观察。接口不提供交易所最终发布完成标记，因此不标成最终全量。空报告、分页不完整或缺少应有买卖席位组会失败；每轮三次重试耗尽后留下失败运行记录，并在下一轮再次检查。已有成功日档不会被后续失败覆盖。

2026-10-16 修正：龙虎榜汇总、买方和卖方席位并非同时发布，当日首次任务因买方报告尚不可用而失败。原稳定任务 ID `stock_billboard_1600` 现改为主机时间工作日 16:00–23:45 每 15 分钟触发，业务层仍使用校准时间和交易日历判断；主机快约五分钟时，首轮等待校准后的 16:00 再采集。成功后后续轮次只检查日档是否存在，跳过上游抓取；三份报告完整后才原子发布当日日档。这个窗口之外没有持续重试，运行状态会保留尚未成功的原因。

## 运维与验证

```bash
# 明确抓取当前榜单并入库；不会伪造历史五分钟记录
python -m app.manually_execute_script.sync_market_observations hot

# 指定一个已经结束的交易日龙虎榜；同日已有日档则幂等跳过
python -m app.manually_execute_script.sync_market_observations billboard --trade-date 2026-10-15
```

调度 ID：`ths_hot_rank_5m`、`stock_billboard_1600` 及各自 `_startup`。成功、失败日志分别为 `market_observation_finished`、`market_observation_failed`。`market_observation_runs` 按任务目标累计 `attempts`，记录最终 `status/error/finished_at`。

本次原始接口样本、重复请求结果、入库前后对比存放在 `.local/analysis/data_sources_20261015/`。实时市场闭市时只能验证协议、归档和异常处理；下一交易日的持续运行需要检查实际调度日志与覆盖率。
