## 秒级数据自动保留：最近五个交易日

2026-10-16 新增长期调度任务 `realtime_snapshot_retention`。调度器启动时检查一次，之后每小时检查；按校准时间确认的非交易日直接跳过清理。任务定义和下次运行时间存入 `apscheduler_jobs`，服务重启后自动恢复。

保留期按 A 股交易日历计算 **5 个交易日**，周末和法定休市日不占名额；保留日的数据整日保留，不使用自然日或 120 小时窗口。

- 以两个原始报价集合中最新已采集、且不晚于校准当前时间的交易日为终点，保留该日及之前 4 个交易日。两个集合使用相同边界。
- 盘前没有新交易日数据时继续保留上一组日期；当天第一批行情入库后，当天才进入新的保留窗口。缺采的交易日仍属于交易日历中的一天，不按有数据的日期冒充完整覆盖。
- 只删除 `stock_realtime_quote_batches`、`stock_realtime_auction_batches` 中早于最早保留日的秒级原始记录，以及 `.local/realtime_quote_spool/` 中对应的过期文件；不删除集合本身。重放待入库文件时也检查交易日边界，避免过期文件重新入库。
- **`stock_realtime_minute_bars` 中全部分钟周期、分钟质量记录、日线、历史研究行情、情绪快照/曲线/事件、热股榜和龙虎榜均不受清理影响。**
- 使用两处 HTTPS 时间校验后的应用时间控制清理，不改系统时钟，也不使用依赖 MongoDB 主机时间的 TTL。校时失败、交易日历未覆盖或没有已采集日期时，不执行删除。10-21 增加本地待写保护后，已落盘且校时可信的新批次也可独立作为本地保留窗口依据，不要求 MongoDB 先写入成功。
- 每批最多删除 100 个文档，批次之间让出执行时间。日志记录保留日期、时间偏移、两个集合的删除数量。正常情况下新数据进入后，在下一次小时检查完成淘汰；不是每秒即时删除。

例如，最新已采集日为 **2026-10-15** 时，保留 **10-09、10-12、10-13、10-14、10-15**；10-16 开始采集后改为保留 **10-12 至 10-16**。国庆长假期间不会因经过多个自然日而清空上一组交易日数据。

过期秒级数据删除后，对应 `/snapshots`、`/auctions` 历史查询会为空；已生成的分钟行情和情绪结果仍可查询，但不能再用已删除的原始批次重建那天完整秒级路径。此策略直接清除过期原始数据，不另留等量冷备份。

MongoDB 删除文档通常先把文件内部空间变为可复用，`df` 不一定立即下降；后续原始报价可复用这些空间。本次不对数据库执行压缩重写或停机整理。

备份位于同一主机，是移出业务库的本地档案，不替代异机灾备。以下示例恢复单个旧档案到**新的恢复库**；`MONGO_URI` 从本地配置提供，不把凭据写入文档，认证库按部署配置调整：

```bash
mongorestore --uri="$MONGO_URI" --authenticationDatabase=admin --gzip \
  --nsInclude='stock_project.quant_daily_results_strategy_archive' \
  --nsFrom='stock_project.*' --nsTo='stock_project_recovered_20261016.*' \
  .local/analysis/database_audit_20261016/dump
```

恢复前先检查清单的文件校验值，并确认恢复库尚不存在。原迁移/补录 CLI 再次运行时仍可能创建自己的临时或审计集合；本次删除没有禁用这些维护功能。旧文档中的迁移时点记录保留作为历史事实，当前集合状态以本清单和实际数据库为准。
